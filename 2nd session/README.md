# 2nd session: Starlink downlink 방식 비교

OFDM, AFDM, OTFS, DD-a-OFDM 비교를 위한 공통 시나리오를 관리한다.
현재 `scenario.json`에는 위성과 지상국의 기하 조건 및 1차 평가 지표 BER을 정의했다.
Ku 다운링크, 공통 반송파 주파수 11.7 GHz, 공통 명목 격자 대역폭 60 MHz를
사용한다. 첫 다중경로 비교용 경로 수·지연·상대 전력·도플러 및 경로 위상의
시행 간 변경 방식과 경로 전력 정규화, 첫 수신 잡음 모델 및 파일럿
공정성 원칙을 정했다. 첫 기준 실험에서는 **LOS 단일경로 + AWGN과 공통
도플러 완전 보정**을 가정한다. `E_b`는 데이터 심볼 에너지 기준이며, 심볼
영역의 잡음 분산 계산 규칙과 에너지 보존형 파형 변환 정규화를 정했다.
첫 기준 실험의 샘플링은 네 방식 모두 **60 MHz, 추가 오버샘플링 없음**으로
정했다. 첫 기준 실험의 유효 프레임은 **주파수 256칸 × 시간 64심볼**로 정했다.
각 `Eb/N0`에서 네 방식 모두 **10,485,760개의 데이터 비트**를 측정한다.
AFDM의 첫 유효 신호 구성은 **256점 IDAFT × 프레임당 64블록**으로 정했다.
OTFS는 **OFDM 기반 ISFFT/SFFT와 직사각형 송수신 펄스**를 사용한다.
유효 파형 변환·채널 추정·기본 MMSE 데이터 복원과 공통 Gray 16-QAM 비트 판정을 구현했다.
전체 고정 비트 수 BER 실행기·중간 저장·그래프 출력을 연결했다.
단일 LOS 기준 실험은 각 방식·시점·지점에서 10,485,760비트로 완료했고, 3경로 본 비교는 실행 중이다.
DD-a-OFDM의 첫 수신 알고리즘은 **DD-ML 채널 추정 + TF 선형 MMSE 등화**로 정했다.
DD-a-OFDM의 순차 초기화·3회 고정 갱신 채널 추정기도 구현하고 예비 검증했다.
후속 3경로 비교의 등화기 종류는 네 방식 모두 **선형 MMSE**로 맞춘다.
OFDM은 BEM-LS 초기 후보, AFDM·OTFS는 아래에서 선정한 프레임 단위 근사 ML/LS를 사용한다.
등화 처리 범위도 정하고, 추정 채널에서 만드는 TF·DAFT 행렬과 전체 DD 연산을 구현·검증했다.
추정 채널을 이용한 파일럿 제거와 데이터 전용 미지수 구성도 구현·검증했다.
잡음 전력은 정답을 제공하는 대신 수신 관측에서 추정하는 방향으로 정했다.
매 프레임 공통 무송신 구간에서 5샘플을 기다린 뒤 256샘플의 평균 전력을 측정한다.
잡음 전력 추정 함수와 수신 구간 검사를 구현·검증했으며 추가 시간은 프레임당 4.35µs다.
무잡음 조건도 별도로 복원해 잡음 추가 전후의 BER을 비교한다.
독립적인 평균 0·에너지 1의 16-QAM 데이터와 추정 채널·측정 잡음 전력을 사용하는
기본 MMSE로 정했다. 별도의 채널 추정 오차 공분산 보정은 추가하지 않는다.
MMSE 입력식과 잡음 측정·추정 채널 연결 및 수치 복원도 구현·검증했다.
OFDM·AFDM·DD-a-OFDM은 블록별 직접 풀이, OTFS는 전체 프레임 CG를 사용한다.
무잡음은 SVD/LSQR 최소제곱으로 풀며, 80개 예비 수신 조건에서 허용오차 검사를 통과했다.
MMSE의 자체 이득을 반영하는 표준 Gray 16-QAM 경판정도 네 방식에 공통으로 적용한다.
별도 수신 실험 변수를 추가하지 않으며, 신뢰구간은 사용자 동의에 따라 95% 프레임 기준으로 보고한다.
후속 파일럿 기반 3경로 비교의 공통 예산은 **파일럿·보호칸 25%, 총 파일럿 에너지
4,096 E_s**로 정했다. 데이터 심볼의 평균 에너지 `E_s=1`은 유지한다.
후속 3경로 비교에서는 네 방식 모두 **256샘플 블록마다 CP 5샘플**을 붙인다.
OFDM과 DD-a-OFDM의 파일럿은 주파수 2칸마다 × 시간 2블록마다 같은 TF 위치에 둔다.
AFDM은 블록당 파일럿 1칸 + 보호칸 63칸, OTFS는 DD 파일럿 1칸과 보호·예약 영역을 둔다.
네 방식 모두 파일럿·보호·예약칸 25%, CP 제외 총 파일럿 에너지 `4,096 E_s`를 유지한다.
파일럿은 방식 안에서 균등한 에너지를 쓰며, 알려진 고정 QPSK 위상열을 사용한다.
OFDM/DD-a-OFDM은 같은 값을 쓰고 AFDM도 같은 기본 위상열을 재사용한다.
수신기 세부 설계와 실제 채널 추정 성능은 계속 논의·검증한다.
OFDM은 **64블록·DPSS 31개 BEM의 순수 LS 계수 추정 시제품**을 구현하고,
데이터 간섭과 AWGN을 포함한 채널 추정 오차를 예비 검토했다. 아래에 그 식과
검증 결과를 남겼으며, 전체 네 방식의 등화·검출·고정 비트 수 BER 실행도 연결했다.
AFDM은 기존 파일럿을 쓰는 **분수 도플러 근사 ML + 복소 이득 공동 LS**를 초기
추정법으로 정하고, 64블록 공동 추정을 구현·검증했다. 모든 수신기에 공통으로
초과 지연 0~5샘플과 잔여 도플러 최대 범위 ±46.875 kHz를 제공한다.
각 경로의 실제 값은 알려주지 않는다. 기본 DAFT 데이터 복원·공통 비트 판정·전체 BER 실행을 연결했다.
OTFS도 기존 DD 파일럿의 전체 분수 도플러 응답을 맞추는 **근사 ML + 공동 LS**로
정하고, 64슬롯 추정기·기본 DD 데이터 복원·공통 비트 판정·전체 BER 실행을 연결했다.

## 첫 기준 실험: 공통 도플러 완전 보정

첫 단계는 네 방식의 기본 송수신 처리와 전력·잡음 정규화가 맞는지 확인하는
기준 실험이다. 채널에는 해당 시점의 궤도에서 계산한 공통 LOS 도플러를
적용하고, 수신기는 채널 생성기와 정확히 같은 도플러 값을 오차 없이 안다고
가정한다. 수신 AWGN을 더한 후 파형별 복조 전에 아래와 같이 보정한다.

`r_corrected[n] = r[n] × exp(-j × 2π × f_D × n / F_s)`

여기서 `f_D`는 선택한 시점의 공통 도플러, `F_s`는 샘플링 주파수다. 보정 후
잔여 공통 도플러는 **0 Hz**다. 이는 실제 도플러 추정기를 구현하는 대신 두는
이상적인 주파수 보정 가정이며, 다른 채널 정보까지 완벽히 안다는 결정은 아니다.
이 단계에서는 도플러 획득용 프리앰블이나 추정 오차 모델을 추가하지 않는다.
후속 3경로용 파일럿과 채널 추정·MMSE 등화의 세부 설계는 아래에 별도로 기록했다.

동일한 데이터 비트 에너지와 이상적인 송수신 처리를 맞추면, 네 방식이 공통
비부호화 16-QAM의 AWGN 기준 BER과 일치하는지 확인할 수 있다. 이 단계의
결과로 도플러 대응 성능의 우열을 판단하지 않는다. 원래의 최고점·이탈 시점
도플러는 기록에 유지하지만, 완전 보정 후에는 두 시점 모두 잔여값이 0 Hz이므로
다른 조건이 같다면 BER 통계도 같아야 한다.

이 기준 실험을 확인한 뒤 다중경로에서의 도플러 영향을 논의한다. 아래의
기존 3경로 지연·전력 프로파일은 유지한다. 후속 비교는 공통 LOS 도플러를
완전히 보정한 A(지연만)와 B(같은 지연 + 경로별 도플러 차이의 단계적 증가)로
정했다. 최대 잔여 도플러는 부반송파 간격의 0·1·5·10·20%로 정했으며,
각 최대 크기 `d`에서 LOS·반사 1·반사 2의 잔여 도플러를 `[0, +d, -d]`로 정했다.
OFDM의 순수 LS 파일럿 추정은 아래 예비 진단을 진행했다. 네 수신기에는
공통으로 초과 지연 0~5샘플의 범위를 제공하며, 실제 지연 0·2·5는 알려주지 않는다.
공통 도플러 탐색 상한은 ±46.875 kHz로 정했다. AFDM·OTFS·DD-a-OFDM은 아래의
고정 탐색 간격·미세 탐색과 아래의 공통 MMSE·비트 판정을 사용한다.
BER 실행과 집계·그래프는 아래의 **고정 비트 수 BER 실행과 95% 신뢰구간**에 기록한다.

실험은 다음 순서로 확장한다. 각 단계의 구체적인 수치와 수신 방식은 해당
단계를 설계할 때 논의한다.

1. LOS 단일경로 + AWGN과 공통 도플러 완전 보정으로 기본 송수신을 확인한다.
2. 파일럿과 CP 등 파형별 보호구간을 설계하고 반영한다.
3. 이미 정한 LOS + 반사 2경로의 다중경로 통제 프로파일을 반영한다.
4. 다중경로에서의 경로별 도플러 차이 또는 보정 오차 등을 근거에 따라 논의한다.

방향으로 정하고 아래의 공통 무송신 구간 측정 함수를 구현·검증했다.
실제 데이터 수신 연결과 등화 조건은 후속 단계다.
후속 3경로 단계의 공통 CP는 아래와 같이 5샘플로 정했다.

신뢰구간의 계산법과 신뢰수준도 정한다. `scenario.json`의

## 채널 구성 순서

첫 비교의 기본 채널은 위성에서 지상국까지의 LOS 단일경로(LOS 포함 총 1경로)로
정했다. 위성 궤도에서 계산한 LOS 도플러를 적용한 뒤 수신기에서 완전히
보정하고, 수신 `Eb/N0`를 바꾸며 BER을 본다. 이는 다중경로를 무시한 통제
실험이지 실제 지상국 주변에 반사가 없다는 주장은 아니다. 이후 LOS를 포함한
다중경로 채널을 별도 비교 조건으로
추가한다. 첫 다중경로 실험은 LOS 1개와 추가 경로 2개, 총 3경로로 정했다.
이는 계산 가능한 통제 모델의 선택이지 해당 지상국에서 실제 측정된 경로
수가 아니다. 첫 다중경로 비교에 사용할 프로파일은 다음과 같다. 지연은 위성에서
지상국까지의 전체 전파시간이 아니라 LOS에 대한 **초과 지연**이다.

| 경로 | LOS 대비 초과 지연 | 60 MHz 기준 샘플 수 | LOS 대비 상대 전력 | LOS 대비 추가 도플러 |
| --- | ---: | ---: | ---: | ---: |
| LOS | 0 ns | 0 | 0 dB | 0 Hz |
| 반사 1 | 약 33.3 ns | 2 | −10 dB | 0 Hz |
| 반사 2 | 약 83.3 ns | 5 | −15 dB | 0 Hz |

두 도플러 시점에서 지연과 상대 전력은 동일하게 유지하고, 각 시점의 궤도에서
계산한 LOS 도플러를 세 경로에 공통으로 적용한다. 수신국과 주변 반사체가
고정된 상황의 첫 근사이며, 반사체의 실제 위치를 모르므로 경로별 추가
도플러를 임의로 주지 않는다. 이는 도플러 **편이**는 포함하지만 경로 간
도플러 **확산**은 포함하지 않는 A의 생성 프로파일이다. 후속 B에서는 아래
도플러 비교 계획에 따라 반사경로의 추가 도플러만 `[+d,-d]`로 바꾼다.
최대 크기와 경로별 부호·상대 크기는 정했다. 위 지연·전력
값은 통제 실험용 선택이지 실제 Starlink–성균관대 링크의 측정치나 표준 NTN 경로
프로파일이 아니다.

이 다중경로 통제 프로파일에서는 각 경로의 크기를 위 상대 전력대로 한 프레임
내내 고정한다.
반사경로의 상대 위상은 독립 BER 시행마다 새로운 무작위 조합을 사용하되,
한 시행의 프레임 안에서는 고정한다. 같은 시행의 네 파형과 저·고도플러
시점에는 동일한 초기 상대 위상 조합을 적용해 도플러 조건만 통제해서
비교한다. 같은 시행의 A/B와 B의 도플러 단계들에도 같은 초기 위상을 쓴다.
A의 생성 프로파일에는 공통 도플러의 위상 회전만 있다. B에는 추가로
`exp(j*2*pi*delta_f_p*t)`의 경로별 결정적 위상 회전이 생기며, 시간은 CP를
포함해 연속으로 흐른다. B의 총 경로 위상까지 프레임 안에서 고정하는 것은 아니다.
별도의 무작위 위상 변화나 경로 크기 변화는 추가하지 않는다. LOS의 초기 위상은
기준값 0으로 두고, 두 반사경로의 위상은 각 시행마다 독립적으로 0~360°의
연속 균등분포에서 선택한다. 이는 측정된 위상 분포라는 뜻이 아니다.

경로 전력은 표의 상대값을 유지하면서 평균 총전력이 1이 되도록 정규화한다.
정규화 전 선형 경로 전력은 `1`, `0.1`, 약 `0.0316`이며, 세 경로의 복소 이득을
모두 `1 / √(1 + 0.1 + 0.0316...)`배 한다. 단일 LOS 조건의 총전력도 1이다.
이는 경로 프로파일에 한 번 적용하는 공통 배율이며, 시행이나 주파수 칸마다
순간 수신 전력을 다시 맞추지는 않는다. 따라서 위상에 따른 보강·상쇄와
경로 간 −10/−15 dB 관계는 남는다. 후속 3경로 비교의 보호구간은 아래 공통 CP
규칙을 사용하고, 나머지 수신기 처리는 계속 논의한다.

## 공통 수신 정보: 첫 3경로 비교

후속 **첫 3경로 파일럿 기반 비교에서는 네 방식 모두 경로 수 `P=3`을 안다**고
합의했다. 같은 사전정보를 사용할 수 있게 하되, 각 알고리즘이 반드시 경로별
파라미터 형태로 채널을 추정해야 한다는 뜻은 아니다.
초과 지연의 공통 탐색 범위는 기존 최대 지연과 CP에 맞춰 **0~5샘플**로 명시했다.
수신기가 그 범위 안의 실제 활성 지연 위치까지 알고 있다는 뜻은 아니다.
잔여 도플러도 최대 범위 **±46.875 kHz**를 네 방식에 공통으로 제공한다.
이 범위는 A/B·잡음 크기에 따라 바꾸지 않으며, 현재 단계의 최대값 `d`나
각 경로의 실제 도플러는 전달하지 않는다. OFDM의 고정 DPSS 대역도 이 범위와 같다.

수신기에 실제 지연 **0·2·5샘플**, 경로별 도플러, 복소 이득의 정답은 제공하지
않고, 파일럿으로 채널을 추정한다. 우선 경로 수 검출 오차를 제외한 파라미터
추정·BER을 비교하기 위한 통제 조건이며, 결과에 경로 수를 알고 있다는 가정을
명시한다. 공통 규칙은 `scenario.json`의 `receiver_information_policy`에 둔다.

이 결정은 첫 단일경로 기준 실험의 공통 도플러 완전 보정을 변경하지 않는다.
후속 A/B의 공통 LOS 도플러도 완전히 보정한다. 경로별 추가 도플러의 정답은
수신기에 주지 않으며, 수신 알고리즘 세부 사항은 계속 논의한다.
경로 수까지 직접 추정하고 그 누락·과대 검출이 BER에 미치는 영향을 보는 실험은
확장 목록에 기록했으며, 검출 방법·문턱값·평가 지표는 아직 정하지 않았다.

## 첫 기준 실험의 샘플링

네 방식 모두 복소 기저대역 신호를 `F_s = 60 MHz`로 계산한다. 추가
오버샘플링 배율은 1이며 별도의 재샘플링을 하지 않는다. 이미 정한 격자에서
`F_s = N × Δf = 256 × 234.375 kHz = 60 MHz`이고, 샘플 간격은 약
16.7 ns, 유효 심볼당 샘플 수는 256이다. 이는 [FFT 크기·부반송파 간격과
샘플링 주파수의 관계](https://www.mathworks.com/help/5g/ug/use-custom-ofdm-sample-rate-and-custom-fft-size.html)에
따른다. 첫 LOS + AWGN 기준 실험의 계산량을 줄이기 위한 디지털 모델의
선택이며, 실제 반송파를 직접 샘플링하는 ADC 사양이라는 뜻은 아니다.

같은 샘플링 주파수만으로 공정성이 보장되지는 않는다. 대역폭·프레임 시간·
데이터 비트 수·비트 에너지와 잡음·채널 및 수신 정보·추가 자원 비용도 함께
맞춘다. 실제 스펙트럼 점유 대역폭과 필터는 이번 결정으로 확정하지 않는다.
시간 방향 64심볼은 첫 기준 실험에 사용하고, 이후 프레임 길이의 영향을 검토한다.

60 MHz는 모든 후속 실험에 영구 고정하는 값이 아니다. 더 자세한 다중경로·
도플러·필터 모델이나 파형 측정을 도입할 때는 네 방식 모두 샘플링을 높여도
BER이 Monte Carlo 불확실성 범위 안에서 유지되는지 확인한다. PAPR이나
스펙트럼 등을 측정한다면 해당 지표의 수렴도 함께 확인한다. 샘플링 배율과
구체적인 판정 기준은 후속 실험을 설계할 때 정하며, 이 검증은 아직 실행하지 않았다.

샘플링을 높여 비교할 때는 물리적인 대역폭·부반송파 간격·프레임 시간·
정보 비트 수·경로 지연과 이득·도플러·에너지 및 자원 비용 기준을 유지한다.
예를 들어 초과 지연 약 33.3 ns와 83.3 ns는 그대로 두고, 이를 표현하는
샘플 수를 바꾼다. 기존 2·5샘플은 60 MHz에서의 값이다. 서로 다른 샘플링
주파수에서는 샘플 간격까지 반영한 물리적 에너지 또는 그와 동등한 정규화
기준으로 신호 배율과 잡음 분산을 다시 계산한다.

## 파형 변환의 에너지 정규화

OFDM, AFDM, OTFS, DD-a-OFDM 모두 유효 신호의 변환 전후 총 에너지를
보존하는 **유니터리 정규화**를 사용한다. 같은 정규화된 이산 샘플 기준에서
입력 격자를 `s_grid`, 출력 유효 신호를 `x_useful`이라 하면 다음을 만족한다.

`sum(|x_useful|²) = sum(|s_grid|²)`

길이가 `L`인 Fourier 변환과 역변환은 각각 `1/√L` 배율을 사용한다.
주파수 방향 256점 변환에서는 각각 `1/16`이다. 2차원 Fourier 변환은 각 축에
이 규칙을 적용한다. 이는 [유니터리 FFT 정규화](https://numpy.org/doc/stable/reference/routines.fft.html#normalization)에
해당하며, 무작위 프레임마다 측정한 전력을 다시 맞추는 방식이 아니다.

OFDM과 DD-a-OFDM의 공통 OFDM 변환뿐 아니라, OTFS 및 DD-a-OFDM의
DD 영역 Fourier 변환에도 같은 원칙을 적용한다. AFDM은 Fourier 부분을
유니터리로 정규화하고, 크기가 1인 chirp 위상 인자를 사용하는 DAFT/IDAFT
쌍으로 에너지를 보존한다. [AFDM의 유니터리 DAFT](https://arxiv.org/pdf/2204.12798)도
복조 변환 전후에 백색 복소 AWGN의 통계가 유지됨을 설명한다. AFDM의
`c1`, `c2` 값이나 각 방식의 채널 추정·등화기는 이 정규화 결정과 별도로 정한다.

이 원칙은 CP 등을 붙이기 전, 수신기에서는 해당 보호구간을 제거한 후의
유효 신호 변환에 적용한다. 파일럿을 격자에 넣으면 그 에너지도 변환 과정에서
보존한다. CP 등 추가 샘플이 만드는 에너지는 따로 계산하며, 전체 프레임을
다시 정규화해 이 비용을 감추지 않는다. 실제 채널이나 등화기가 에너지를
보존해야 한다는 가정은 아니다. OTFS의 유효 파형 변환은 `otfs.py`에 구현했으며,
네 파형의 전체 BER 송수신 구성은 아직 구현하지 않았다.

## 잡음 모델

첫 BER 비교에는 복소 AWGN(가산성 백색 가우스 잡음)을 사용한다. LOS와
반사경로의 신호를 합친 뒤 수신단에서 잡음을 한 번만 더하며, 경로마다
별도의 잡음을 넣지 않는다. 잡음은 평균 0이고 샘플 간 독립인 모델로 둔다.
이는 파형 비교를 위한 통제 가정이며 실제 Ku 다운링크의 간섭·위상잡음 등
모든 손상을 재현한다는 뜻은 아니다. 잡음 적용은 아직 구현하지 않았다.

첫 기준 실험의 `E_b`는 **파일럿과 CP 등 보호구간의 에너지를 제외한 데이터
심볼 기준**으로 정의한다. 비부호화 16-QAM은 한 심볼당 4비트이고 평균 심볼
에너지가 1이므로, 정규화된 데이터 비트 에너지는 `E_b = E_s / 4 = 1/4`이다.
이 에너지 계산 기준은 실제 신호에서 파일럿이나 보호구간을 생략한다는 결정과는
별개다. 기존 파일럿 자원·에너지 공정성 원칙은 유지하며, 전체 전송 에너지를
정보 비트 수로 나눈 기준은 파일럿·보호구간 설계 이후 별도로 평가할 수 있다.

`gamma_b = 10^(Eb/N0[dB] / 10)`일 때, 정규화된 **데이터 심볼 영역**에서의
복소 잡음 분산은 `sigma_s² = E_s / (4 × gamma_b) = 1 / (4 × gamma_b)`로
계산된다. 실수부와 허수부의 분산은 각각 `sigma_s² / 2`다. 예를 들어
`Eb/N0 = 10 dB`이면 심볼 기준 복소 잡음 분산은 0.025, 각 성분의 분산은
0.0125다. 이는 [Eb/N0와 Es/N0의 관계](https://www.mathworks.com/help/comm/ug/awgn-channel.html)와
[복소 AWGN의 성분별 분산](https://www.mathworks.com/help/comm/ref/awgnchannel.htm)에 따른 계산이다.

심볼 기준 잡음은 독립적인 표준 정규 난수 `u, v`를 사용해
`n_s = sqrt(sigma_s² / 2) × (u + jv)`로 표현한다. 이 식의 분산을 실제 수신
파형 샘플에 적용할 때는 확정한 유니터리 변환 규칙을 사용한다. 같은 이산
샘플 격자에서 정방 유니터리 송수신 변환을 사용하고, 추가 재샘플링이나
필터 이득이 없으면 유효 시간 샘플의 복소 AWGN 분산도
`sigma_time² = sigma_s² = 1 / (4 × gamma_b)`다. 수신 유니터리 변환이
백색 복소 잡음의 공분산을 보존하기 때문이다. 첫 샘플링 격자는 60 MHz로
확정했다. 필터는 별도 설계 항목이며, 후속 실험의 재샘플링이나 필터에서
다른 배율이 생기면 실제 샘플 분산의 관계를 다시 계산한다.
매 시행의 순간 수신 전력을 측정해 잡음 세기를 다시 맞추지는 않는다.

## 첫 기준 실험의 프레임 길이

첫 LOS + AWGN 기준 실험에는 주파수 방향 256칸과 **시간 방향 64심볼**을
사용한다. `Δf = 234.375 kHz`이므로 보호구간을 제외한 유효 심볼 길이는
`1/Δf ≈ 4.267 µs`, 64심볼 길이는 약 `0.273 ms`다. 60 MHz 샘플링에서
유효 프레임은 `256 × 64 = 16,384`샘플이며, 명목 도플러 칸 간격은 약
`3.66 kHz`다. 후속 3경로 비교에서는 슬롯마다 CP 5샘플을 붙여 실제 전송 시간이
**278.4 µs**, 명목 도플러 칸 간격이 **약 3.592 kHz**가 된다. 아래의 공통 파일럿
자원·에너지 예산은 유지하며, 실제 데이터·파일럿 마스크는 아래 파일럿 비교 절과
`pilot_layouts.py`에 정의했다. 알려진 복소 파일럿 값도 고정 시퀀스로 구현했다.

64는 계산 규모를 정해 첫 실험을 시작하기 위한 값이며, 궤도에서 결정되거나
적절성·최적성이 검증된 값은 아니다. [DD-a-OFDM 참고 논문 표 I](https://arxiv.org/pdf/2508.04253#page=10)도
시간 방향 64심볼을 사용하지만 부반송파 간격이 15 kHz여서 프레임 시간은 약
4.27 ms다. 따라서 논문의 64심볼은 이번 약 0.273 ms 프레임에 그대로 적합하다는
근거가 아니다. 실제 실행시간과 프레임 길이에 따른 결과는 아직 측정하지 않았다.

후속 검토에서는 다른 프레임 길이의 실행시간과 BER을 확인한다. 이상적인
LOS + AWGN 기준에서는 변조·에너지·잡음 조건을 같게 하고 충분한 비트와
오류를 누적해 BER 통계가 일치하는지 확인한다. 이후 다중경로·시간 변화 채널을
비교할 때는 프레임 길이에 따라 관측 시간과 도플러 격자, 추정기 동작도 달라질
수 있으므로 결과가 같아야 한다고 요구하지 않는다. 각 길이에서 네 방식의
전송 자원을 맞추고 차이를 해석한다. 추가 길이와 판정 기준은 추후 정하며,
이 검증은 아직 실행하지 않았다.

현재 이탈 시점의 공통 도플러 절댓값 약 261 kHz는 부반송파 간격
234.375 kHz보다 크다. 시간 심볼 수만 늘려서는 심볼 간 도플러 관측의
모호성을 해결할 수 없다. 첫 단일경로 기준 실험에서는 채널 생성기가 사용하는
공통 도플러를 수신기도 정확히 알고, 파형별 복조 전에 완전히 보정한다고
가정하므로 이 큰 주파수 이동의 획득 문제는 제외한다. 첫 기준 실험은 위의
64심볼을 사용한다. 아래의 CP 결정은 후속 3경로 비교에 적용하며, 실제 파일럿
배치와 도플러 추정·추적 방법은 별도로 설계한다. 후속 채널 비교에 사용할 프레임
길이는 검토 결과에 따라 재평가한다.

## 공통 보호구간: 후속 3경로 비교

네 방식 모두 **유효 신호 256샘플마다 CP 5샘플**을 붙이고, 수신기에서 제거한
후 유효 샘플을 복조한다. 기준은 기존 경로 0·2·5샘플의 **LOS 대비 최대 초과
지연 5샘플**이다. 위성에서 지상국까지의 전체 전파시간을 CP 길이로 쓰는 것은 아니다.

이는 정렬된 수신 구간과 현재의 정수 샘플 지연 모델에서의 최소 길이다.
시간 정렬 오차·분수 지연 필터의 꼬리·더 큰 지연 범위를 도입하면 다시 검토한다.
구체적인 시간 동기화 획득 알고리즘을 이번에 선택한 것은 아니다.

| 항목 | 후속 3경로 비교 설정 |
| --- | ---: |
| 유효 블록 | 256샘플 |
| 블록별 CP | 5샘플, 약 83.33 ns |
| 전송 슬롯 | 261샘플, 4.35 µs |
| 프레임 | 64슬롯, 16,704샘플 |
| CP 샘플 합계 | 320샘플 |
| 실제 프레임 시간 | 278.4 µs |
| 명목 도플러 격자 간격 | 약 3,591.954 Hz |

부반송파 간격은 유효 구간 기준 **234.375 kHz**를 유지한다. 도플러 위상과 채널
재구성에는 CP를 포함한 시간축을 사용한다. 슬롯 `n`의 유효 샘플 `q`는 첫 CP
샘플을 시간 원점으로 두면 `((256+5)*n+5+q)/F_s`에 해당한다.

AFDM은 현재 `N=256`이 짝수이고 `2*N*c1=5`가 정수이므로 CPP가 일반 CP와
같아진다. [AFDM 논문 식 (19) 뒤의 조건](https://arxiv.org/pdf/2204.12798#page=9)을
사용하며, `N`이나 `c1`이 바뀌면 이 조건을 재검토한다. OTFS는
[각 슬롯에 붙이는 CP](https://www.mathworks.com/help/comm/ug/otfs-modulation.html)를
채택한다. 프레임 전체에 CP 하나만 붙이는 RCP 구성과 구분한다.

`cyclic_prefix.py`의 공통 함수는 끝 샘플을 그대로 복사하고, 크기 조절이나
프레임 전력 재정규화를 하지 않는다. CP 에너지는 복사된 샘플의 제곱 크기 합으로
별도 기록한다. **같은 CP 길이가 같은 CP 에너지까지 보장하지는 않는다.**
데이터 `E_s=1`, 총 파일럿 에너지, 데이터 심볼 기준 `Eb/N0` 잡음 규칙은 유지한다.
파일럿·보호칸 25%의 분모는 계속 유효 격자 16,384칸이며, CP는 별도 시간 비용이다.

```powershell
python check_cyclic_prefix.py
```

CP 추가·제거, 에너지 집계, 정적 3경로의 선형 채널과 슬롯별 순환 채널의 일치를
검증했다. 상대 채널 계산 오차는 약 `1.06e-16`, CP를 4샘플로 줄인 비교용 사례의
불일치 오차는 약 `0.01295`다. 이 값은 파형 상대 오차이며 BER이 아니다.
AFDM의 CP/CPP 등가성과 OTFS의 CP 포함 복원도 허용오차 `1e-12` 이내였다.
기존 `check_otfs_transform.py`의 CP 없는 기본 변환 검증도 통과했다.

첫 단일경로 LOS + AWGN 기준 실험과 공통 도플러 완전 보정 가정은 유지한다.
이 CP 결정은 후속 3경로 단계의 설계다. 해당 단계의 도플러 보정 정책과 추정·등화
수치 설정은 계속 미정이며, DD-a-OFDM의 기존 DD-ML/TF 선형 MMSE 선정은 유지한다.
이번에는 공통 CP 함수와 OTFS 연결을 구현·검증했고, 다른 파형의 전체 송수신기와
BER 실험은 계속 구현할 항목이다.

## AFDM의 첫 블록 구성

AFDM은 **256점 IDAFT를 한 블록에 적용하고, 프레임마다 64블록을 연속으로
전송**한다. 수신기는 각 블록에 대응하는 256점 DAFT를 사용한다. 변환은
앞서 정한 유니터리 정규화를 따른다. 비교 기준 OFDM의 유효 심볼 단위와
AFDM의 유효 블록 단위를 다음처럼 맞춘다.

| 방식 | 송신 변환 단위 | 프레임당 개수 | 한 단위의 유효 샘플 수 |
| --- | --- | ---: | ---: |
| OFDM | 256점 IFFT | 64심볼 | 256 |
| AFDM | 256점 IDAFT | 64블록 | 256 |

60 MHz 샘플링에서 두 방식 모두 한 단위의 유효 길이는 약 4.267 µs,
프레임 전체는 16,384샘플이며 CP 등을 제외하면 약 0.273 ms다. AFDM의
`c1`, `c2` 선정식에 사용하는 블록 길이는 **`N_AFDM = 256`**이며,
전체 프레임 샘플 수 16,384와 구분한다. 첫 기준 실험에서는 프레임 전체를
한 번에 처리하는 16,384점 DAFT 구성을 채택하지 않는다.

`c1`, `c2`의 초기값과 위의 후속 3경로 CP 규칙을 정했다. 파일럿 배치 및
채널 추정·등화 세부 사항은 아직 정하지 않았다. 같은 블록 시간만으로
모든 비교 조건이 동등해졌다는 뜻은 아니다. BER용 AFDM 송수신기는 아직
구현하지 않았으며, 아래의 rank 점검은 별도의 수치 진단이다.

### c1의 설계 기준

`c1`은 **선택한 통과 구간 전체의 보정 전 공통 LOS 도플러 최대 절댓값**을
기준으로 설계했다. 채택한 지원 범위 안에서 첫 기준 실험,
저·고도플러 시점, 프레임 및 `Eb/N0`별로 같은 값을 고정해 사용한다.
매 시점의 실제 도플러에 맞춰 `c1`을 다시 조절하지 않는다. 이후 채널의
설계 범위를 변경하면 파라미터도 명시적으로 재검토한다.

현재 고정 궤도와 지상국, 11.7 GHz를 사용해 통과 구간을 0.25초 간격으로
탐색하고 양 끝점을 포함하면, 최대 절댓값은 **약 261.029 kHz**이며 이탈
시점인 `2026-07-29 07:51:02.674 UTC`에서 나타난다. 0.125초 간격으로도
같은 반올림 결과를 확인했다. 경사거리 변화율은 각 시각의 앞뒤 0.5초,
총 1초 간격의 중앙차분으로 계산했다. 이는 해당 통과의 수치적 추정값이며
모든 Starlink 통과의 최대값이나 실측값은 아니다.

이때 AFDM의 블록 기준 도플러 간격은 `F_s / N_AFDM = 234.375 kHz`이며,
최대 절댓값은 약 **1.11372416칸**이다. 이를 전체 64블록 프레임의 명목 DD
격자 간격과 구분한다. 전체 프레임의 간격은 CP가 없으면 약 3.66 kHz,
후속 CP 5샘플을 적용하면 약 3.592 kHz다.

정규화된 도플러를 `nu = alpha + a`로 나누며, `alpha`는 정수이고 분수 성분은
`-0.5 < a <= 0.5`를 만족한다. 현재 설계 범위에서 정수 성분의 최대 절댓값은
**`alpha_max = 1`**이다. 매 시점의 실제 도플러가 항상 1칸이라는 뜻은 아니다.
분수 도플러 여유의 초기값은 **`xi_nu = 1`**로 정했다.
[AFDM 논문 III-E절 식 (43)](https://arxiv.org/pdf/2204.12798#page=13)을 적용해
다음 값을 사용한다.

```text
c1 = (2 * (alpha_max + xi_nu) + 1) / (2 * N_AFDM)
   = (2 * (1 + 1) + 1) / (2 * 256)
   = 5/512 = 0.009765625
```

이는 합의한 초기 설계값이며 최적성이나 BER 성능을 검증한 값은 아니다.
`xi_nu = 1`은 분수 도플러의 영향이 한 칸 안에 모두 들어간다는 보장이나
수신기에서 주변 성분을 잘라내라는 설정이 아니다. 채널에는 실제 분수
도플러를 유지하며, 파일럿·보호칸 배치와 수신기 근사는 별도로 논의한다.
기존 3경로 통제 프로파일의 최대 초과 지연 **5샘플(60 MHz에서 약 83.3 ns)**은
후속 경로 분리·블록 내 수용 조건을 검토할 때 사용한다. 다중경로와 수신기
처리를 도입할 때 여유의 적절성을 확인한다. 첫 도플러 완전 보정 LOS + AWGN
실험으로는 이 여유의 도플러 대응 성능을 판단할 수 없다.

이 설계 기준을 사용해도 첫 LOS + AWGN 기준 실험에서는 실제 공통 도플러를
완전히 보정해 잔여값을 **0 Hz**로 둔다. 새로운 경로별 도플러나 미보정
실험 조건을 추가한 것은 아니다. 날짜·궤도·반송파·지상국 또는 AFDM의
샘플링·블록 길이가 바뀌면 지원 범위와 정규화된 도플러를 다시 계산한다.

### c2의 선정과 3경로 rank 점검

사용자가 구체적인 값의 선정을 위임하여 **`c2 = sqrt(2) / N_AFDM^2`**를 선택했다.
현재 `N_AFDM = 256`이므로 다음 값을 사용한다.

```text
c2 = sqrt(2)/65536 = 0.000021579186437577746 (수치 근삿값)
```

[AFDM 논문 IV절·VII절·부록 A](https://arxiv.org/pdf/2204.12798)는 경로 분리 등
논문의 조건 아래에서 신호 차이 행렬의 rank를 확보하는 무리수 `c2` 선택을
설명한다. 위의 구체적인 식은 이를 참고한 이번 실험의 설계 선택이다.
`N_AFDM^2`로 나누면 블록 내 심볼 인덱스 `m`에 대한 `c2*m^2`의 크기를
대략 일정한 규모로 유지할 수 있다. 최적 BER을 보장하는 식으로 해석하지 않는다.
정확한 설계식은 무리수이며, 컴퓨터에서는 배정밀도 근삿값으로 계산한다.

rank 조건은 서로 다른 송신 벡터의 차이 `delta = x - x' != 0`에 대해
`Phi(delta) = [H_1*delta, ..., H_P*delta]`의 열 rank가 경로 수 `P`가 되는 것이다.
계획한 **LOS + 반사 2개, 지연 0·2·5샘플**에서는 `Phi`가 **256행 3열**이고
목표 rank는 **3**이다. DAFT 변환 자체는 유니터리이며, 그 변환 행렬의 rank와
위 신호 차이 행렬의 rank를 구분한다. 첫 단일경로 기준 실험부터 후속 3경로
조건까지 같은 `c2`를 프레임·`Eb/N0`·저/고도플러 시점에 걸쳐 고정해 사용한다.
블록 길이나 지연·도플러 설계 범위를 바꾸면 파라미터를 명시적으로 재검토한다.

`check_afdm_rank.py`는 이상적인 순환 지연 블록에서 경로별 이득을 제외한
`H_i`를 구성해 수치 점검한다. 이는 충분한 보호구간으로 순환 블록을 구현한
경우의 진단 모델이다. 합의한 CP와 선형 채널의 관계는 위의 CP 점검에서 별도로
검증했고, 실제 채널 추정·등화기의 세부 사항은 계속 미정이다.
잔여 공통 도플러는 0 Hz로 두며, 새로운 경로별 도플러를 추가하지 않는다.

```powershell
python check_afdm_rank.py
```

시드 `20261103`으로 단일 위치 차이 256개, 두 위치 차이 1,024개, 무작위 조밀
16-QAM 차이 1,024개와 주기·comb·위상 패턴 21개를 검사했다. 총 **2,325개**에서
모두 상대 SVD 문턱값 `1e-10` 기준 **rank 3**이며, 관측한 최소 특잇값 비율
`sigma_min/sigma_max`는 약 **0.57735**다. 이 점검은 모든 가능한 송신 벡터 쌍에
대한 증명이나 BER 실험이 아니다. 첫 단일경로 기준 실험으로 3경로 다이버시티를
판단하지 않으며, 경로 크기가 고정된 LOS 우세 통제 모델에서 경로 수만으로
다이버시티 차수가 3이라고 주장하지 않는다.

### AFDM 채널 추정법의 초기 선정 — 2026-11-04

사용자와 **embedded pilot 기반 분수 도플러 근사 ML로 지연·도플러를 찾고,
복소 이득은 공동 LS로 구한 뒤 DAFT 영역 선형 MMSE에 연결**하는 초기 구조를 정했다.
[AFDM 원 논문 VI절 식 (67)~(76)](https://arxiv.org/pdf/2204.12798#page=19)을
근거로 하며, 분수 도플러를 정수 칸으로 반올림하지 않는다. ML은 채널 파라미터
추정 단계다. 데이터 판정에 완전 탐색 ML을 추가하는 제안은 아니다.
아래 관측 구성을 검증한 뒤, 추정 구간과 탐색 설정도 함께 정하고 구현했다.

기존 `c1=5/512`, `c2=sqrt(2)/65536`, 256샘플 블록 64개, 블록별 CP 5샘플과
파일럿·보호칸·에너지 예산을 유지한다. 수신기에 실제 0·2·5 지연이나 경로별
도플러·이득을 주지 않고, 공통 `P=3`과 지연 범위 0~5를 사용한다.

`afdm.py`는 네이티브 IDAFT/DAFT와 분수 도플러 파일럿 응답을 제공한다.
시간 채널을 `exp(+j*2*pi*f*t)`로 정의했을 때, 파일럿의 수신 중심 위치는
대략 `(f*N/Fs - 2*N*c1*l) mod N`이다. 이 부호는 우리 시간 채널과 직접 대조했다.
응답의 복소 이득 기준은 블록의 첫 유효 수신 샘플이며, 프레임 기준으로 합치려면
`exp(+j*2*pi*f*((N+CP)*b+CP)/Fs)`를 포함해야 한다.

송신에서 비운 64칸을 그대로 수신의 파일럿 관측 구간으로 쓰면, 지연에 의해
옮겨진 데이터가 섞인다. 합의한 방법의 논문 VI절 관측식을 현재 수치에 적용하면
0 기반 **`0..2`와 `229..255`**, 블록당 30개 DAFT 관측값이다.
`R=alpha_max+xi_nu=2`, `S=2*N*c1=5`로 각 지연 후보의 중심 `-S*l` 주변
`±R`을 합친 구간이다. 전송 파일럿을 추가하는 것이 아니며, 기존 블록당 파일럿
1개·보호칸 63개와 총 파일럿 에너지 4096은 유지한다. 64블록이면 관측 1920개다.

```text
y_E,b ≈ pilot_b * Σ_p g_p,b a_E(l_p,f_p) + 데이터 누설 + 수신 잡음
```

후보별 지연·분수 도플러에 맞는 파일럿 응답을 수신값과 비교하고, 주어진 후보에서
이득을 공동 LS로 구한다. 논문의 근사 ML은 경로 사이 응답의 겹침이 작다는 근사를
사용한다. 유한 보호칸과 분수 도플러에서는 데이터 누설·경로 겹침이 남으므로,
우리 조건에서 이를 정확한 ML 우도나 완전한 간섭 분리라고 주장하지 않는다.

`review_afdm_estimator.py`와 `data/afdm_estimator_review.json`에 구조 검토를 남겼다.

```powershell
python review_afdm_estimator.py --output data/afdm_estimator_review.json
```

직접 만든 IDAFT 행렬과 네이티브 파형의 상대 차이는 약 `3.46e-14`, 정수 지연
0~5와 양·음 분수 도플러에서 직렬 시간 채널과 파일럿 응답식의 상대 차이는
약 `1.40e-13` 이하였다. CP 포함 시간축과 블록별 알려진 QPSK 파일럿 위상도 포함했다.
파일럿 유효 에너지는 4096, 별도로 측정한 파일럿 CP 성분 에너지는 80이었다.

기존 A/B 채널에서 16개의 데이터·초기 위상 실현으로 수신 구간을 확인했다.
제안 구간에서 수신 데이터 에너지/파일럿 성분 에너지 비는 A에서 수치 오차
수준, B-4에서 약 **−38.58 dB**였다. 송신의 비데이터 64칸을 그대로 관측한 경우에는
A에서도 약 **−16.08 dB**로, 수신 구간을 구분해야 하는 이유를 확인했다.
이 비율은 채널 추정 오차나 BER이 아니며, 방식 간 성능 순위를 뜻하지 않는다.
또한 지연 0~5와 도플러 401개 구조 탐색에서 제안 구간이 포함한 단일 경로 파일럿
에너지의 최소 비율은 약 **98.38%**로, 분수 도플러의 꼬리가 남는 것도 확인했다.

이 구조 검사 자체는 경로 탐색이나 AWGN·등화·비트 판정을 수행하지 않는다.
별도의 아래 구현에서 경로 탐색과 AWGN 입력까지 확인했다. 실제 지연이 서로
다르다는 생성 조건을 추가 정답 정보로 주거나 탐색 제약으로 강제하지 않았다.

#### 64블록 공동 추정과 수치 탐색 설정

원 논문의 AFDM 프레임은 우리 실험의 256샘플 블록 하나다. 사용자는 OFDM과
같은 관측 시간을 쓰도록 **64블록 공동 추정**을 선택했다. 송신은 기존 블록 구성을
유지하고, 한 프레임 안에서 유지되는 지연·도플러·프레임 기준 이득을 공동 추정한다.
다른 독립 프레임의 위상을 하나로 이어서 추정하지 않는다.

| 항목 | 합의한 초기 설정 |
| --- | --- |
| 추정 구간 | CP 포함 64블록, 16,704샘플·278.4 µs |
| 수신 파일럿 응답 관측 | 30칸 × 64블록 = 1,920개 |
| 공통 도플러 상한 | 네 방식 모두 ±46,875 Hz, 실제 경로 값과 현재 A/B 단계는 제공하지 않음 |
| 초기 주파수 간격 | `1/(4*T_frame)` = 약 897.989 Hz |
| 초기 격자 | 대칭 격자에 0 및 양쪽 상한을 포함한 107개 주파수 × 6개 지연 = 642개 후보 |
| 미세 탐색 | 선택한 후보 주변의 연속 주파수 구간을 1 Hz 이하로 좁힘 |
| 순차 탐색 | 알려진 경로 수만큼 3번, 매 단계 이미 찾은 경로의 이득까지 공동 LS 갱신 |

분수 도플러는 정수 칸이나 1 Hz 격자로 반올림하지 않는다. **1 Hz는 미세 탐색의
수치 종료 기준이며 실제 추정 오차가 1 Hz 이내라는 보장이 아니다.** 초기 격자와
종료 기준은 모든 A/B·`Eb/N0`·시행에 고정하고, 실제 경로 주파수를 격자에 끼워 넣지 않는다.
별도의 외부 반복이나 데이터 판정 피드백은 추가하지 않았다.

`afdm_estimation.py`의 공동 관측행렬은 경로 후보마다
`pilot_b * exp(+j*2*pi*f*t_b) * a_E(l,f)`를 블록 순서로 쌓아 만든다.
`t_b=((256+5)*b+5)/F_s`이며, LS 이득의 기준 시각은 프레임 첫 CP 샘플 `t=0`이다.
따라서 64개 블록의 복소 파일럿 위상과 CP 시간에 의한 위상 누적을 모두 반영한다.

순차 탐색에서는 이미 찾은 경로의 공간을 제거한 후보 에너지로 잔차 상관을
정규화해 점수를 구한다. 이는 기존 경로 파라미터를 고정했을 때 공동 LS 오차를
얼마나 줄이는지에 해당한다. 초기 후보 주변은 bounded golden-section 방식으로
좁히고, 경로를 하나 추가할 때마다 전체 선택 경로의 이득을 LS로 다시 구한다.
이는 선택한 공동 프레임용 **근사 비선형 탐색**이며, 전체 조합을 탐색하는 전역 ML이나
원 논문의 블록별 수치 알고리즘을 그대로 재현한 것으로 주장하지 않는다.

추정기에는 `channel_model`, 데이터 정답, 실제 경로 값, 잡음 분산을 주지 않는다.
파일럿에 섞인 데이터는 관측 잔차로 남긴다. 추정 이득을 다시 전력 정규화하지 않으며,
추정된 경로들로 CP 포함 시간축의 탭을 재구성한다. 같은 지연·서로 다른 도플러의
경로도 표현할 수 있고, 수치적으로 같은 응답의 중복만 식별 불가능으로 처리한다.

```powershell
python check_afdm_estimation.py --trials 16 --output data/afdm_estimation_check.json
```

이 검증은 독립 직렬 채널을 사용한다. 알려진 후보의 LS 계산 검증에서 관측행렬과
직렬 채널의 상대 차이는 약 `3.22e-14` 이하였다. 그 밖에 실제 프로파일과 다른
지연 조합 및 같은 지연에 다른 도플러가 있는 조합도 순수 파일럿으로 검사했다.
이들은 구현 검사이며 새로운 본 실험 채널을 선택한 것이 아니다.

실제 경로를 입력받지 않는 탐색에는 A/B마다 16프레임을 사용해 데이터와
무잡음·기존 0~30 dB의 7개 AWGN 점을 넣었다. 총 640개 입력에서 추정값의
유한성·범위·rank 3, 단계별 LS 잔차 감소와 1 Hz 이하 수치 종료를 확인했다.
기존 프로파일의 지연 조합도 이 진단에서는 모두 복원했다. **경로 추정기 구현을
확인한 것이며, BER이나 네 방식의 성능 순위를 구한 결과는 아니다.**
기존 BER 비트 수·종료 기준은 유지하고, 남은 추정 오차는 이후 BER에 반영한다.
OTFS와 DD-a-OFDM 추정법도 아래와 같이 정하고 구현·예비 검증했다.
각 방식의 추정 채널 연산과 기본 MMSE 데이터 복원·공통 Gray 비트 판정을 구현했다. 전체 BER 실행도 아래처럼 연결했다.

## OTFS의 첫 송수신 구조

**OFDM 기반 OTFS와 직사각형 송수신 펄스**를 채택했다. 데이터는 지연 256칸 ×
도플러 64칸에 배치하고, ISFFT로 주파수 256칸 × 시간 64칸으로 변환한다.
각 시간 슬롯의 256점 IFFT가 송신 시간 파형을 만든다. 수신기는 슬롯별 FFT와
SFFT로 DD 관측값을 얻고, 이후 DD 선형 MMSE 등화·심볼 판정을 수행하는 방향으로
정했다. 이후 전체 DD 프레임 처리 범위와 추정 채널 연산을 구현했으며,
추정 채널 기반 파일럿 제거와 아래 공통 잡음 측정·기본 MMSE 입력식의 연결도 구현했다.
MMSE 수치 풀이와 표준 이득 처리·Gray 데이터 판정 및 전체 BER 실행도 아래처럼 연결했다.
[MathWorks의 OTFS 설명](https://www.mathworks.com/help/comm/ug/otfs-modulation.html)을
참고하되, 예제의 패딩·채널·파일럿·배율 대신 이번에 합의한 조건과 유니터리
정규화를 사용한다.

배열은 지연 또는 주파수를 행, 도플러 또는 시간을 열로 둔다.

| 단계 | 배열의 행 | 배열의 열 | 크기 |
| --- | --- | --- | --- |
| DD 입력 | 지연 `l` | 도플러 `k` | 256 × 64 |
| ISFFT 출력 | 주파수 `m` | 시간 슬롯 `n` | 256 × 64 |
| 시간 파형 | 슬롯 내 샘플 `q` | 시간 슬롯 `n` | 256 × 64 |

```text
X_tf = FFT_delay(IFFT_Doppler(X_dd))        # ISFFT
s[q,n] = IFFT_frequency(X_tf)[q,n]          # 슬롯별 OFDM 변환
Y_tf = FFT_sample(r[q,n])
Y_dd = FFT_time(IFFT_frequency(Y_tf))       # SFFT
```

각 FFT/IFFT는 축 길이의 제곱근으로 정규화한다. CP 추가 전 유효 신호의 직렬화
인덱스는 `q + 256*n`으로 각 슬롯의 256샘플을 연속 배치한다. CP를 포함한 실제
스트림의 유효 샘플 위치는 위 공통 보호구간 절의 시간축을 사용한다.
변환 내부에 `fftshift`를 넣지 않는다.
유효 샘플 수는 **16,384**, 보호구간 제외 유효 프레임 시간은 약 **0.273 ms**로
공통 기준과 같다. 직사각형 펄스는 유효 슬롯의 시간창 선택이며, 실제 RF 필터나
점유 대역폭 마스크를 정한 것은 아니다.

`otfs.py`는 ISFFT/SFFT와 변조·기저 복조를 제공한다. 기본 `cp_length=0`은 기존
유효 신호만 처리하며, 후속 3경로 단계의 `cp_length=5`는 슬롯별 CP를 내부에서
추가·제거한다. 수신 입력의 시간 정렬은 호출자가 처리한다. 공통 CP 및 파일럿
자원·총 에너지 예산과 아래의 DD 파일럿 마스크를 적용한다.
알려진 파일럿은 `64+0j`로 고정했다. DD 선형 MMSE를 등화기 종류로 정했으며,
채널 추정법과 전체 DD 프레임의 채널 연산은 아래에서 선정·구현했다.
MMSE 수치 풀이와 표준 이득 처리·심볼 판정 및 전체 BER 실행은 아래처럼 연결했다.
이번 구현으로 새로운 동기화 가정이나 전체 채널 지식을 부여하지 않는다.

```powershell
python check_otfs_transform.py
```

이 점검은 3×2 및 4×5 격자의 직접 이중합 수식과 FFT 구현을 비교하고,
256×64 격자에서 복원·에너지 보존·직사각형 펄스의 역 Zak 표현과의 일치를
확인한다. 시드 `20261103`, NumPy 2.3.5에서 무작위 16-QAM 격자 8개와 DD
임펄스 4개를 검사했다. 최대 상대 복원 오차는 약 `5.15e-16`, 에너지 오차는
약 `4.45e-16`, 역 Zak 표현과의 차이는 약 `1.40e-14`로 상대 허용오차 `1e-12`
이내였다. 잡음이나 채널을 적용한 BER 실험은 아니다.

### OTFS 채널 추정법의 초기 선정과 검증 — 2026-11-04

기존 DD 파일럿의 **전체 분수 도플러 응답을 맞추는 근사 ML + 경로 이득 공동 LS**를
초기 방법으로 정했다. 사용자는 64슬롯 전체 관측과 AFDM과 같은 약 898 Hz 초기
탐색·1 Hz 이하 구간까지의 미세 탐색도 함께 수락했다. 이후 추정 채널을 이미
합의한 DD 선형 MMSE에 넘긴다. 이 절에서 구현한 범위는 채널 추정과 탭 재구성이다.

[기존 OTFS 참고 논문](https://arxiv.org/pdf/1808.08360)은 embedded DD 파일럿과
분수 도플러용 full-Doppler 보호영역을 설명하지만, 기본 채널 추정은 문턱값 방식이며
데이터 검출은 message passing이다. 이번의 연속 도플러 파일럿 응답 맞춤·공동 LS와
DD 선형 MMSE 조합은 우리 실험을 위해 선택한 방법이다. 논문의 추정기를 그대로
재현한 것으로 부르지 않는다. 한 경로가 여러 도플러 칸으로 퍼지므로 가장 큰 칸
3개를 경로 3개로 취급하는 대신, 각 경로가 만드는 응답 전체를 계산한다.

| 항목 | 합의한 초기 설정 또는 그에 따른 관측 영역 |
| --- | --- |
| 추정 구간 | CP 포함 64슬롯, 16,704샘플·278.4 µs |
| 수신 파일럿 응답 | 지연 128~133행 × 도플러 전체 64칸 = 384개 관측값 |
| 수신기에 주는 경로 정보 | 공통 `P=3`, 초과 지연 정수 0~5샘플, 고정 도플러 범위 ±46,875 Hz |
| 초기 탐색 | `1/(4*T_frame)` ≈ 897.989 Hz; 107개 주파수 × 6개 지연 = 642개 후보 |
| 미세 탐색 | 후보 주변 연속 주파수 구간을 1 Hz 이하로 좁힘; 실제 추정 정확도 보장은 아님 |
| 순차 탐색 | 3번 경로 추가, 매번 모든 선택 경로의 복소 이득을 공동 LS 갱신 |

관측 행은 새 파일럿 배치가 아니라 현재 변환과 지연 범위에서 유도된다. 슬롯의
주파수 FFT/IFFT가 상쇄되어 유효 시간 신호는 DD 격자의 도플러 축 IFFT와 같다.
따라서 지연 128의 파일럿은 슬롯 내 샘플 128에 있고, 지연 `l`을 거치면 DD의
`128+l`행에 도착한다. 현재 정수 지연·CP 조건에서는 도플러가 그 행의 64칸에만
퍼진다. 기존 보호·예약칸이 데이터 유입을 막으므로 송신 파일럿 1칸, 총 파일럿
에너지 `4,096 E_s`, 데이터 12,288칸과 비데이터 25% 예산을 그대로 사용한다.
이 성질은 현재 시간 정렬·정수 지연·직사각형 변환에 대한 것이며, 분수 지연이나
물리 필터를 추가하면 다시 검토한다.

`otfs_estimation.py`는 경로 후보 `(l,f)`의 단위 이득 응답을 다음과 같이 계산한다.
FFT는 64슬롯 축의 유니터리 변환이고, 응답은 DD의 `128+l`행에 놓는다.

```text
t_b = ((256+5)*b + 5 + 128+l) / Fs
a_lf[k] = FFT_b[(64/sqrt(64)) * exp(j*2*pi*32*b/64) * exp(j*2*pi*f*t_b)]
y_p = A(paths) * gains + noise
```

복소 이득은 첫 송신 CP 샘플 `t=0` 기준이다. CP 시간과 슬롯 내 파일럿 도착 위치를
모두 반영하고, 도플러를 DD 칸으로 반올림하지 않는다. 분수 도플러 응답 자체는
현재 격리된 정수 지연 모델에서 정확히 계산하지만, 3단계 비선형 경로 탐색은
**순차 근사**이므로 전역 ML 최적해나 정확한 파라미터 복원을 보장하지 않는다.
같은 지연·서로 다른 도플러의 경로도 허용한다. 추가 외부 반복·데이터 판정 피드백은
선택하지 않았고, 실제 경로 값·송신 데이터·잡음 분산을 추정기에 주지 않는다.

AFDM과 OTFS의 같은 수치 탐색은 `pilot_path_search.py`로 공유한다. 기존 AFDM
탐색을 그대로 옮겼고, 추정 결과가 유지되는 회귀 검사도 통과했다.
두 방식의 고유 관측값과 응답 계산은 각각의 추정 모듈에서 처리한다. 같은 관측 시간과
탐색 설정을 쓴다는 사실만으로 두 파일럿 구조의 정보량이나 모든 수신 조건이 같아지는
것은 아니다. 이번 비교에서는 합의한 송신 자원·에너지 예산 아래 각 설계의 BER을 본다.

```powershell
python check_otfs_estimation.py --trials 16 --output data/otfs_estimation_check.json
```

독립 직렬 채널과 단위 경로 응답을 비교한 78개 지연·주파수 검사에서 최대 상대 차이는
약 `1.02e-14`, 데이터만 보낸 경우 관측 영역으로의 누설은 파일럿 L2 크기 대비 약
`9.64e-17` 이하였다. 다른 지연 조합·같은 지연에 다른 도플러·탐색 상한의 경로도
별도 수학 검사로 확인했다. 이 조합들은 새로운 본 실험 채널을 선정한 것이 아니다.

A/B 5조건마다 16프레임을 사용해 데이터와 무잡음·기존 0~30 dB의 7개 잡음 조건을
넣었다. 총 640개 입력에서 추정값의 유한성·범위·rank 3, 순차 LS 잔차 감소와
1 Hz 이하 미세 탐색 종료를 확인했고, 이 진단의 실제 프로파일 지연 조합은 모두
복원했다. **채널 추정 구현 검사이며 BER이나 네 방식의 순위를 구한 결과는 아니다.**
남은 추정 오차는 이후 BER 비교에 반영하고, 기존 측정 비트 수와 종료 기준을 유지한다.

## DD-a-OFDM의 초기 수신 구조

참고 구조는 [DD-a-OFDM 논문 v2](https://arxiv.org/pdf/2508.04253v2)의 II-B절·그림 1과
IV절을 기준으로 기록한다. 확인한 버전은 2026-05-10 개정본이다.
송신은 공통 256개 부반송파 × 64개 시간 심볼의 OFDM 구조를 유지하고,
기존 공정성 원칙에 따라 OFDM과 같은 TF 파일럿 위치를 사용한다.
논문의 구체적인 파일럿 간격이나 5경로 설정을 이번 실험에 복사하지 않는다.

논문의 수신 흐름은 **TF 파일럿 관측 → DD 채널 파라미터 추정 → TF 채널행렬
재구성 → TF 등화·QAM 판정**이다. DD 영역은 채널 추정에 사용하고, 데이터의
등화는 TF 영역에서 수행한다. 송신 데이터에 OTFS의 ISFFT를 추가하는 구조는 아니다.
같은 TF 심볼·파일럿·프리픽스·펄스를 넣으면 OFDM과 DD-a-OFDM의 송신 파형은
같으므로, 두 방식의 BER 차이는 송수신 방식 비교에 포함된 추정·수신 처리 차이로
해석한다.

다음 알고리즘 조합을 **첫 구현 기준으로 확정**했다.

- **DD 채널 추정:** IV-A절 Algorithm 1의 ML 추정. 경로별 지연·도플러를 번갈아
  갱신하고, 복소 이득은 함께 LS 갱신하는 alternating projection 방식을 사용한다.
- **TF 등화:** IV-B절 식 (43)–(44)의 ICI를 포함한 전체 채널행렬 선형 MMSE. 우리 격자에서는
  시간 심볼마다 256×256 행렬을 구성하며, 프레임에는 64개 시간 심볼이 있다.

ML은 파일럿 관측으로 경로의 지연·도플러·복소 이득을 추정하는 단계이며,
추정값으로 TF 채널행렬을 구성한다. 선형 MMSE는 그 추정 채널과 수신 데이터를
이용해 심볼을 복원하는 단계다. QAM 판정과 비트 복원은 그 뒤에 수행한다.

경로 수 정보는 위의 공통 수신 정보 규칙에 따라 **첫 3경로 비교에서 알려준다**.
채널 생성기에 LOS + 반사 2개를 설정한 것과 수신기가 경로 수를 아는 것은
별도 가정이며, 이번에는 이를 네 방식에 같은 가용 정보로 명시했다.
논문의 Algorithm 1은 추정 경로 수를 입력받으며, IV-A절은 문턱값에 의한 경로 수
판별도 설명한다.

초기 3경로 비교에서는 경로 수 `P=3`과 초과 지연 범위 `0~5샘플`을 공통으로 제공하고,
실제 활성 지연·도플러·복소
이득은 파일럿으로 추정한다. 경로 수 판별은 후속 확장으로 분리한다. 알고리즘
조합과 추정기 수치 설정은 아래와 같이 정했으며, 데이터 수신기의 나머지 정보 조건은 계속 미정이다.

OFDM/DD-a-OFDM의 파일럿 간격은 주파수 2칸 × 시간 2블록으로 정했다.
파일럿 값·방식 내 균등 에너지 배분과 공통 도플러 상한, 초기화·탐색·외부 반복을 정했다.
추정기는 아래처럼 구현·예비 검증했다. 잡음 전력은 아래 공통 무송신 측정으로 구하며,
그 수신 연결과 데이터 등화 조건은 후속 단계다.
공통 LOS 도플러를 완전히 보정하고 A는 잔여 `[0,0,0]`, B는 합의한 `[0,+d,-d]`를
유지한다. 전체 데이터 수신기나 BER 실험을 구현·실행한 결과는 아니다.

### DD-a-OFDM의 외부 반복 횟수 결정 — 2026-11-04

사용자는 **초기 추정 후 외부 반복 3회 고정, 수렴에 따른 조기 종료 없음**을 수락했다.
초기 추정은 이 3회에 포함하지 않는다. 한 번의 외부 반복은 경로 1·2·3의 지연과
도플러를 차례로 갱신한 뒤, 세 경로의 복소 이득을 공동 LS로 다시 구하는 과정이다.
따라서 초기 추정 이후 경로 파라미터 갱신은 총 9번, 전체 이득 공동 LS는 총 3번이다.
경로 수 `P=3`과 외부 반복 3회는 별개의 설정이다.

[참고 논문 Algorithm 1](https://arxiv.org/pdf/2508.04253v2#page=9)은 각 경로를 갱신한 뒤
공동 LS를 수행하는 외부 반복을 정의한다. [논문의 실험 설정](https://arxiv.org/pdf/2508.04253v2#page=11)도
`Numiter=3`을 사용하므로 초기값의 근거로 삼았다. 논문에 함께 적힌 내부 탐색 횟수
`Numsearch=8`은 이번에 선택한 값이 아니다. 외부 반복 3회가 우리 조건에서도 충분하거나
전역 ML 최적해를 보장한다는 뜻은 아니며, 구현 검증에서 반복 부족 여부를 확인한다.

모든 A/B·`Eb/N0`·프레임/시행에 동일한 3회를 적용한다. 실제 경로 정답이나 BER,
현재 도플러 실험 단계에 따라 횟수를 바꾸지 않는다. 검증에서 한계가 드러나면 기록하고,
반복 횟수 변경은 별도로 함께 정한다. 추정 오차를 전부 줄여야 BER 비교로 넘어갈 수
있다는 조건을 추가한 것은 아니다.

이후 초기화·탐색 수치도 아래와 같이 정하고 추정기를 구현했다.
기존 10,485,760비트 측정량·종료 규칙은 유지하며, BER 실행 결과는 아직 없다.

### DD-a-OFDM의 초기화·탐색 설정과 구현 검증 — 2026-11-04

사용자는 경로를 하나씩 찾아 **총 3개로 초기화한 뒤, 외부 반복을 정확히 3회** 수행하는
방식을 수락했다. 초기화에서는 경로를 추가할 때마다 선택한 경로들의 복소 이득을
공동 LS로 다시 구하고 잔차를 갱신한다. 외부 반복에서도 같은 범위를 탐색한다.

| 항목 | 합의한 초기 설정 |
| --- | --- |
| 관측 구간 | 기존 64슬롯 한 프레임, CP 포함 278.4 µs |
| 관측 파일럿 | TF의 128개 주파수 행 × 32개 시간 열 = 4,096개 |
| 지연·도플러 범위 | 공통 정수 지연 0~5샘플, 고정 ±46,875 Hz |
| 거친 탐색 | `1/(4*T_frame)` ≈ 897.989 Hz; 양끝·0을 포함한 107개 주파수 × 6개 지연 |
| 미세 탐색 | 선택한 후보 주변에서 golden-section 탐색, 남은 구간이 1 Hz 이하이면 종료 |
| 초기화 후 갱신 | 모든 경로를 차례로 갱신하고 공동 LS, 이 과정을 3회 고정 수행 |

1 Hz는 수치 탐색의 종료 기준이며 물리 도플러의 반올림 간격이나 정확도 보장이 아니다.
초기화는 외부 반복 3회에 포함하지 않는다. 모든 A/B·`Eb/N0`·시행에서 설정을 고정한다.
실제 지연·도플러·복소 이득, 송신 데이터와 잡음 분산은 추정기에 제공하지 않는다.
같은 지연에서 도플러가 다른 경로도 허용하며, 수치적으로 구분 불가능한 중복만 제외한다.

[논문 식 (19)~(25)](https://arxiv.org/pdf/2508.04253v2#page=5)의 흐름에 따라
수신 TF 파일럿을 알려진 값으로 나누어 파일럿 위치의 CTF를 얻고, DD 영역으로 옮긴다.
`dd_a_estimation.py`는 128×32 파일럿 격자에 주파수 축 유니터리 IFFT와 시간 축 FFT를
적용한다. 이는 256×64 격자에 0을 채워 SFFT한 결과의 한 주기를 알려진 배율로 정규화한
것과 같고, 4,096개 관측값의 에너지를 보존한다. 파일럿 자원이나 에너지를 추가하지 않는다.

추정 응답은 논문에서 분리한 **원래 부반송파에 남는 성분**을 사용한다. 다른 부반송파에서
넘어오는 ICI는 알려진 파일럿에서 오든 미지 데이터에서 오든 잔차로 남긴다. 정확한 전체
파일럿 응답을 새로 맞추거나 정답 데이터로 간섭을 제거하는 알고리즘으로 바꾸지 않았다.
고정 QPSK 파일럿과 16-QAM 데이터를 쓰는 우리 조건에서 논문의 간섭 독립성·Gaussian
가정까지 입증했다고 주장하지 않는다. 이 working model 아래의 수치 ML 근사다.

물리 경로 이득을 첫 CP 샘플 `t=0` 기준으로 복원하기 위해, 경로 `(l,f)`의 TF 응답은
다음 식을 DD로 변환해 계산한다. `m`과 `b`는 실제 파일럿 주파수·슬롯 인덱스다.

```text
C(f) = mean_{q=0,...,255} exp(j*2*pi*f*q/Fs)
a_tf[m,b] = C(f) * exp(j*2*pi*f*((256+5)*b+5)/Fs) * exp(-j*2*pi*m*l/256)
```

`C(f)`는 블록 안 도플러 때문에 원래 부반송파에 남는 복소 계수다. 이를 포함해 LS를
풀면 논문의 유효 이득과 물리 경로 이득 사이의 배율·위상을 반영할 수 있다. 추정 이득을
다시 전력 정규화하지 않고, CP 시간을 포함하는 프레임 전체의 시간 변화 탭을 재구성한다.
이후 아래 공통 채널 연산에서 256×256 TF 행렬 구성과 기본 MMSE 수치 풀이를 구현·검증했다.

초기화는 AFDM·OTFS와 같은 순차 탐색 원리를 사용한다. 외부 반복의 경로 갱신에서는
다른 경로의 현재 기여분을 빼고 정규화 상관을 최대화한다. 이 점수에서 제거한 목표
경로의 복소 진폭은 조건부 스칼라 LS로 복원하고, 모든 경로 갱신 뒤 공동 LS를 수행한다.
이전 경로 후보도 유지해 격자를 다시 탐색한다는 이유로 적합도가 강제로 나빠지지 않게 한다.
이는 수치 구현 규칙이며 외부 반복이나 데이터 피드백을 추가하는 것이 아니다.

```powershell
python check_dd_a_estimation.py --trials 16 --output data/dd_a_estimation_check.json
```

78개 지연·주파수 검사에서 독립적인 직접 성분 계산과의 최대 상대 차이는 약
`2.02e-14`, 직렬 단일 부반송파 채널과의 차이는 약 `3.75e-15`였다. 다른 지연 조합,
같은 지연에 서로 다른 도플러가 있는 조합, 탐색 상한의 경로도 별도 수학 검사로 확인했다.
이 검사들은 생성기 정답을 받는 수신기나 새로운 본 실험 프로파일을 추가한 것이 아니다.

실제 직렬 채널에는 데이터와 고정 파일럿을 모두 보내고, A/B별 16프레임에 무잡음 및
기존 0~30 dB의 7개 잡음 조건을 적용했다. 640개 입력 모두 범위·유한성·rank 3,
초기 경로 3개 추가 후 정확히 외부 반복 3회, 1 Hz 이하 미세 탐색과 LS 잔차 비증가를
통과했다. 지연 조합도 이 소규모 진단에서는 모두 복원했다. 간섭은 평가에서만 알려진
파일럿 ICI와 미지 데이터 ICI로 나누어 기록하며, 추정기가 이를 정답으로 빼지 않는다.

현재 프로파일은 서로 다른 정수 지연이어서 원하는 DD 응답이 서로 직교하는 지연 행에
놓인다. 이 진단에서 마지막 외부 반복의 목적함수 변화는 저장 정밀도상 0이었다.
반면 같은 지연의 별도 순수 모델 검사에서는 반복 갱신으로 추정이 개선되는 것을 확인했다.
일반적인 채널에서도 3회면 수렴한다는 보장은 아니다. 남은 추정 오차는 이후 BER에
반영하며, 이 결과로 네 파형의 BER 순위를 판단하지 않는다.

공유 미세 탐색 코드를 함수로 분리한 뒤 AFDM·OTFS의 기존 예비 검사도 다시 통과했다.
추정 채널행렬·등화 범위와 파일럿 처리, 공통 잡음 측정과 기본 MMSE 입력식도 아래처럼 구현했다.
수치 풀이와 공통 표준 비트 판정도 아래처럼 구현·검증했으며, 남은 단계는 전체 BER 연결이다.

## 공통 등화기와 채널 추정법의 선정 상태

후속 파일럿 기반 3경로 A/B 비교의 등화기 종류는 네 방식 모두 **선형 MMSE**로
정했다. 각 수신기가 파일럿에서 얻은 채널 추정값으로 행렬을 구성해 사용한다.
공통 `P=3` 사전정보와 LOS 공통 도플러 완전 보정은 유지하며, 실제 경로 지연·추가
도플러·복소 이득의 정답을 수신기에 제공하는 가정은 추가하지 않는다.

| 방식 | 구체적인 채널 추정법 | 합의한 등화 영역·종류 |
| --- | --- | --- |
| OFDM | 64블록·DPSS 31개 순수 BEM-LS 시제품과 채널 NMSE 예비 진단, 전체 추정법 적합성 검토 중 | TF 선형 MMSE |
| AFDM | 64블록 공동 embedded-pilot 근사 ML + 공동 LS 이득 선정·구현·예비 검증 | DAFT 선형 MMSE |
| OTFS | 64슬롯 전체 DD 파일럿 응답 근사 ML + 공동 LS 이득 선정·구현·예비 검증 | DD 선형 MMSE |
| DD-a-OFDM | 순차 초기화 + DD-ML AP 3회 고정·공동 LS 구현·예비 검증 | 기존 TF 행렬 선형 MMSE |

[DD-a-OFDM 논문 V-D절](https://arxiv.org/pdf/2508.04253v2#page=13)은
OFDM과 DD-a-OFDM에 ICI를 고려하는 MMSE 등화기를 함께 사용한다.
네 방식 모두 선형 MMSE를 쓰는 것은 이번 실험에서 합의한 공통 기준이다.
각 수신기가 추정한 시간 변화 탭에서 ICI를 포함한 TF·DAFT 행렬과 전체 DD 연산을 구성한다.
처리 범위와 구성, 추정 채널을 이용한 파일럿 제거·데이터 미지수 구성은 아래처럼 정했다.
잡음 전력은 아래의 공통 무송신 측정으로 추정한다.
데이터 공분산은 `E_s*I`, 기본 MMSE의 잡음 항은 측정한 AWGN 전력으로 정했다.
채널 추정 오차에 별도의 공분산 보정은 추가하지 않으며, 수치 풀이는 아래 공통 정확도 기준으로 구현했다.
같은 등화기 이름만으로 모든 수신 조건이 같아지는 것은 아니다.
기존 DD-a-OFDM의 심볼당 256×256 TF 행렬 64개 구성은 유지한다.
등화기 종류와 처리 범위를 합의하고 채널 연산까지 구현한 상태다.
전체 데이터 수신기나 BER을 구현·실행한 결과는 아니다.

OFDM은 BEM 기반 LS 후보의 처리 구간을 한 프레임 64블록, 초기 기저를
DPSS/Slepian 31개로 정했다. 순수 LS 파일럿 추정식과 예비 진단은 아래에 추가했으며,
데이터 간섭·프레임 끝 오차를 포함한 추정법의 적합성은 계속 검토한다.
AFDM은 64블록 공동 embedded-pilot 근사 ML/LS를 선정하고 구현·예비 검증했다.
OTFS도 64슬롯 DD 파일럿 응답 근사 ML/LS를 선정하고 구현·예비 검증했다.
DD-a-OFDM도 순차 초기화·AP 3회 고정 갱신을 구현·예비 검증했다.
모든 방식의 기본 MMSE 수치 복원과 표준 출력 이득 처리·비트 복원도 아래처럼 구현했다. 전체 BER 연결은 남아 있다.
관련 채널 추정·검출 방법은 문헌에 존재한다.
공통 설정은 `scenario.json`의 `receiver_equalization_policy`에 기록한다.

### 등화 처리 범위와 추정 채널 연산 — 2026-11-04

사용자는 **OFDM·AFDM·DD-a-OFDM은 256칸씩, OTFS는 DD 256×64 프레임 전체**를
함께 고려하는 처리 범위를 수락했다. 각 수신기가 자기 파일럿에서 추정한 채널을 사용하고,
그 채널에 포함된 칸 사이 간섭을 모두 유지한다. 한 칸씩만 처리하는 등화나 분수 도플러
커널의 임의 절단은 선택하지 않았다.

| 방식 | 채널 표현 범위 | 구현 |
| --- | --- | --- |
| OFDM | 슬롯별 TF 256×256, 프레임당 64개 | BEM-LS 추정 탭에서 전체 ICI 행렬 구성 |
| AFDM | 블록별 DAFT 256×256, 프레임당 64개 | 추정 탭과 고정 DAFT 변환으로 전체 행렬 구성 |
| DD-a-OFDM | 슬롯별 TF 256×256, 프레임당 64개 | 경로 추정에서 재구성한 탭으로 전체 ICI 행렬 구성 |
| OTFS | 전체 DD 격자 256×64; 개념적 16,384×16,384 연산 | 큰 행렬을 저장하지 않고 정확한 정방향·켤레전치 연산 제공 |

이 크기는 파일럿·보호·예약칸을 포함한 **전체 유효 격자의 채널 표현**이다. 파일럿 처리
이후 실제로 풀 데이터 미지수는 아래에서 프레임당 12,288개로 구성했다.
데이터 공분산과 MMSE 잡음 항은 아래 기본 통계 모델로 정하고 입력식을 구현했다.
네 방식은 같은 64슬롯 프레임을 사용하지만, 고유 신호 확산 범위에 맞춰 처리한다.
처리 차원을 같게 해야 같은 수신기가 된다는 뜻이나 모든 수신 조건이 같다는 주장은 아니다.

현재 정렬된 정수 초과 지연 0~5샘플을 CP 5샘플이 덮으므로, CP를 제거한 시간 채널은
슬롯별로 분리된다. 유효 샘플 `q`, 블록 `b`의 시간 채널은 다음과 같다.

```text
n = (256+5)*b + 5 + q
r_b[q] = sum_l h_hat[n,l] * s_b[(q-l) mod 256]
```

도플러가 만드는 샘플별 변화는 `h_hat[n,l]`에 그대로 남긴다. 블록 평균이나 도플러
반올림, 블록마다의 위상 초기화는 하지 않는다. OTFS의 DD 심볼은 여러 시간 슬롯에
걸쳐 퍼지므로, 시간 채널이 슬롯별로 분리되어도 DD 채널은 프레임 전체를 연결한다.

`channel_operators.py`는 각 추정기의 `model.reconstruct_taps(estimate)` 결과를 받아
CP를 포함한 실제 수신 시각에서 유효 탭을 선택한다. OFDM은 6개 후보 탭의 BEM 추정값을
그대로 쓰고, 나머지 방식도 추정 경로가 같은 지연에 있으면 합산된 탭을 쓴다. 생성기의
실제 지연을 보고 탭을 없애거나 추정 이득을 다시 정규화하지 않는다.

파형별 유니터리 송신 변환을 `S`라 하면 채널은 `H_native = Sᴴ H_time S`다.
OFDM·DD-a-OFDM에는 슬롯별 IFFT, AFDM에는 고정 IDAFT, OTFS에는 기존 프레임 변환을
적용한다. `apply`는 이 전체 채널 곱셈을, `adjoint`는 켤레전치 곱셈을 수행한다.
`adjoint`는 채널 역행렬이나 데이터 복원 결과가 아니다. 이후 MMSE 수치 풀이에 쓸 연산이다.
TF·DAFT의 `block_matrix(b)`는 각 블록의 전체 행렬을 반환한다.

OTFS는 시간 영역의 지연별 곱셈·순환 이동과 기존 변환을 조합한다. CP가 시간을 분리하는
구조를 이용하므로 DD 간섭을 잘라내지 않고도 큰 행렬 저장을 피할 수 있다. 현재 유효
추정 탭 배열은 1.5 MiB이며, 가상으로 전체 복소 행렬을 저장하면 4 GiB가 필요하다.
이는 배열 크기 비교이며 전체 프로그램 메모리나 실행시간 측정값은 아니다.

```powershell
python check_channel_operators.py --output data/channel_operator_check.json
```

A/B×네 방식의 20개 수학 검사와 일반적인 시간 변화 6탭의 네 검사를 독립 직렬 채널과
비교했다. 슬롯 행렬과 직접 연산의 최대 상대 차이는 약 `6.81e-16`, 켤레전치의 차이는
약 `5.79e-16` 이하였다. 켤레전치 내적 검사의 최대 오차는 약 `7.83e-18`이었다.
작은 OTFS 격자에서는 독립적으로 만든 전체 행렬과 비교해 정방향·켤레전치 상대 차이가
각각 약 `3.38e-16`, `3.31e-16` 이하였다. 분수 도플러 응답의 64개 도플러 칸이 모두
남는 것과 짧은 CP의 거부도 확인했다. 작은 격자와 임의 6탭은 수학 검사이며 본 실험 조건을
바꾸는 선택이 아니다.

또 A와 B-4의 진단용 `Eb/N0=20 dB`에서 각 수신기를 실제로 실행한 8개 경우의 추정
탭을 연결했다. 재구성한 채널의 직렬 예측과 네이티브 연산이 일치했다. 정답 탭을 수신기에
준 결과가 아니며, 추정 채널과 실제 채널이 같다는 증명도 아니다. 기존 추정 오차는 유지한다.
전체 검사의 상대 허용오차는 `1e-11`이었고, 채널 생성·파일럿·CP·측정 비트 수는 유지했다.

이 단계의 구현은 채널 연산까지였다. 이어 아래에서 파일럿 성분 처리와 데이터 미지수
구성도 구현했다. 아래의 잡음 측정·기본 MMSE 입력식 연결과 수치 풀이·종료 기준을 검증했으며,
표준 출력 이득 처리·비트 판정도 아래처럼 연결했으며, 전체 BER 측정은 후속 단계다.

### 추정 채널로 파일럿 제거·데이터 미지수 구성 — 2026-11-04

사용자는 네 방식 모두 **추정 채널로 알려진 파일럿 수신 성분을 계산해 빼고, 데이터
칸만 미지수로 복원**하는 공통 처리를 수락했다. 파일럿·보호·예약칸의 송신 위치와 값,
총 파일럿 에너지, 데이터 심볼 크기와 기존 CP는 유지한다.

전체 송신 격자를 `x=P_data*d+p`로 쓴다. `p`는 알려진 파일럿만 채우고 나머지는
0인 격자이며, `P_data`는 데이터 벡터 `d`를 기존 데이터 칸에 배치하는 연산이다.
`pilot_data_model.py`는 다음 입력 문제를 준비한다.

```text
r_data = r - H_hat*p
A_hat = H_hat*P_data
A_hat^H = P_data^H*H_hat^H
```

여기서 `H_hat`은 해당 수신기가 자기 파일럿으로 추정한 채널이다. 생성기의 실제 채널을
사용하지 않는다. 복원할 송신 미지수의 열만 데이터로 줄이며, **수신 관측 행은 모두 유지**한다.
간섭으로 데이터가 송신 파일럿·보호·예약 위치에 해당하는 수신 칸에도 도달할 수 있으므로,
수신 격자를 데이터 마스크로 잘라내지 않는다. 이 관측 규칙은 선택한 전체 채널 모델에서
데이터 열만 추출한 결과다.

| 방식 | 데이터 전용 연산의 크기 — 수신 관측 × 미지수 |
| --- | --- |
| OFDM·DD-a-OFDM | 파일럿이 있는 짝수 슬롯 32개는 각각 256×128; 나머지 32개는 256×256 |
| AFDM | 64개 블록 각각 256×192 |
| OTFS | 전체 DD 프레임의 16,384×12,288 연산, 큰 행렬을 만들지 않고 계산 |

어느 방식이든 프레임의 데이터 미지수는 총 **12,288개**다. 기존 열 우선 배치 순서를
유지하고, 데이터·파일럿·프레임 전력을 다시 정규화하지 않는다. 이 크기는 기존 마스크와
이번 처리 규칙에서 유도한 값이며 새로운 파일럿 예산을 선정한 것이 아니다.

순서는 원래 수신 샘플로 채널 추정 → 추정 채널 구성 → 전체 데이터 수신 격자 복조 →
파일럿 성분 제거다. 데이터 수신 격자는 OFDM·DD-a-OFDM에서 TF, AFDM에서 DAFT,
OTFS에서 DD다. 파일럿 제거한 값을 다시 채널 추정에 넣거나 정답 데이터를 피드백하는
반복은 추가하지 않는다. 원래 수신 관측도 수정하지 않는다.

파일럿을 완벽히 제거하는 가정은 아니다. 실제 채널이 `H`라면 잔여 파일럿 성분은
`(H-H_hat)*p`이고, 데이터 전용 추정 모델에 대한 전체 잔차는 다음과 같다.

```text
r_data - A_hat*d = (H-H_hat)*(P_data*d+p) + w
```

채널 추정 오차와 AWGN을 그대로 남기며, 잔여 파일럿 오차를 독립 백색 Gaussian 잡음으로
간주하거나 추가로 제거하지 않는다. AWGN 전력은 아래 공통 무송신 측정으로 추정하며,
그 값을 아래의 기본 MMSE 입력식·수치 풀이·표준 비트 판정과 전체 BER 실행에 연결했다.
**이 파일럿 처리 구현은 MMSE 입력을 준비하는 단계이며 데이터 복원 결과가 아니다.**

```powershell
python check_pilot_data_model.py --output data/pilot_data_model_check.json
```

채널이 일치하는 A/B×네 방식의 수학 검사 20개에서 파일럿 제거 후 데이터 연산과의
최대 상대 차이는 약 `4.60e-16`이었다. 데이터 열 행렬·켤레전치와 직접 연산의 차이는
약 `5.88e-16`, 내적 검사의 오차는 약 `9.09e-18` 이하였다. 네 개의 의도적인 채널
불일치 검사에서는 예상한 파일럿 잔여 성분이 남았고, 그 항등식의 오차는 약 `5.61e-15`
이하였다. 이 불일치 값은 수학 검사이며 새 추정 오차 분포를 선정한 것이 아니다.

실제 수신기를 실행한 A/B-4·진단용 `Eb/N0=20 dB`의 8개 연결 검사에서는 각 방식의

항등식이 약 `8.03e-15` 이내에서 일치했다. 모든 경우 전체 수신 관측과 원래 데이터
순서·전력 배분을 유지했다. 기존 추정기·채널·측정 비트 수는 바꾸지 않았고,
이 파일럿 제거 검사 자체에서는 MMSE 수치 풀이·심볼 판정·BER을 실행하지 않았다.
뒤의 절에 수치 풀이와 표준 비트 판정의 별도 구현·검증을 기록한다.

### 잡음 전력 추정과 잡음 추가 전후 비교 — 2026-11-04

사용자는 네 방식 모두 **잡음 전력을 수신 관측에서 추정해 MMSE에 사용하는 방향**과,
**같은 데이터·채널의 무잡음/잡음 조건을 별도로 복원해 BER을 비교하는 방향**에 동의했다.
이후 별도 답변으로 **공통 무송신 측정 구간**을 선택하고, **매 프레임 5샘플 대기 후
256샘플 측정**을 초기 설정으로 정했다. 잡음 전력 추정 함수와 수신 구간 검사는 구현·검증했으며,
아래의 기본 MMSE 입력식과 연결하는 예비 검사도 추가했다.
기본 MMSE 수치 복원까지의 예비 수신 검사도 아래에 기록한다.
전체 프레임 생성기·비트 판정·BER과의 연결은 아직 완료하지 않았다.
설정은 `receiver_equalization_policy.noise_information_policy`에 기록한다.

잡음 샘플 자체를 알아서 빼는 가정과 잡음의 평균 전력을 추정하는 과정은 구분한다.
시뮬레이터는 기존 데이터 심볼 기준 `Eb/N0`에서 실제 AWGN 분산을 정해 잡음을 생성하지만,
이 분산·목표 `Eb/N0`·데이터 구간에 더한 잡음 샘플·깨끗한 수신 신호를 수신기 입력으로
제공하지 않는다. 생성·평가 측은 정답을 보관해 추정 오차와 BER을 측정할 수 있다.
잡음 전력 추정값으로 실제 주입할 잡음을 다시 조절하거나 프레임 전력을 재정규화하지 않는다.
정확한 공통 LOS 도플러 보정과 기존 공통 설계 정보는 그대로 유지한다.

[공식 채널 추정 구현](https://www.mathworks.com/help/5g/ref/nrchannelestimate.html)은
알려진 기준 심볼의 수신 관측으로 채널과 잡음 분산 추정값을 출력하고,
[공식 MMSE 구현](https://www.mathworks.com/help/5g/ref/nrequalizemmse.html)은 추정된
잡음 분산을 입력받는다. 이는 관측 기반 잡음 전력 추정의 예이며, 해당 구현의 추정법이나
자원 배치를 우리 네 수신기에 그대로 채택한 것이 아니다.

현재 파일럿 제거 후 관측에는 미지 데이터가 남고, 채널 추정 잔차에도 데이터 간섭·
모델 오차가 섞인다. 따라서 이들 관측의 평균 제곱 크기를 순수 AWGN 전력으로 바로 쓰지 않는다.
송신에서 비워 둔 칸도 수신에서는 지연·분수 도플러에 따른 신호가 들어올 수 있으므로,
모든 방식의 보호·예약칸을 잡음 전용 관측이라고 취급하지 않는다.

다음 두 관측 방법을 비교 검토한 뒤 첫 번째를 선택했다. 가능한 모든 추정법을
이 두 가지로 제한한다는 뜻은 아니다.

| 후보 | 장점 | 추가 가정·비용과 남은 결정 |
| --- | --- | --- |
| 네 방식 공통의 무송신 잡음 측정 구간 — 선정 | 신호가 도착하지 않는 구간을 보장하면 채널 추정 오차와 분리해 같은 방식으로 측정 가능 | 추가 시간과 측정/데이터 구간의 같은 잡음 통계 가정 필요 |
| 기존 파일럿 관측을 활용 — 미선정 | 새 측정 시간을 추가하지 않을 수 있음 | 데이터 간섭·채널 모델 오차·적합에 따른 잡음 흡수를 다뤄야 하며, 네 수신기에 적용할 방법과 편향 검증 필요 |

기존 잡음 모델의 평균이 0이므로, 신호가 없는 수신 관측 `z[m]`에 대해
**`sigma_hat² = mean(|z[m]|²)`**로 복소 잡음 전력을 추정한다. I와 Q의 전력을 모두 포함하며,
평균을 빼거나 `L-1`로 나누지 않는다.
[잡음 전용 관측의 ML 전력 추정 연구](https://cris.unibo.it/retrieve/handle/11585/802184/78cc746a-e562-4d62-ba22-f30493ca800a/TWC2982880.pdf)의
식 (18)에도 이러한 형태가 나온다. 해당 연구는 스펙트럼 검출에 관한 것이며 Starlink의
실제 프레임 구조나 무송신 구간 존재를 입증하지 않는다. 공통 무송신 구간은 우리 통제 실험에
추가하는 설계이며, 데이터에 더한 잡음 벡터를 따로 건네는 것으로 대체하지 않는다.

송신을 멈춘 뒤에도 이전 신호가 최대 초과 지연만큼 도착할 수 있다. 현재 공개 지연 범위가
0~5샘플이므로 앞의 5샘플을 버리고 뒤의 256샘플만 측정한다. 실제 경로 위치를 보고
대기 길이를 줄이지 않는다. 이 대기는 추가 CP가 아니며, 물리 필터·지연 범위·동기화
가정이 바뀌면 다시 검토한다. 잡음 측정 구간은 모두 송신 0으로 두고, 데이터 프레임은
기존 첫 CP 샘플을 시간 기준 0으로 유지한다.

| 시간·자원 항목 | 초기 설정 |
| --- | ---: |
| 지연 성분을 기다리는 시간 | 5샘플, 약 0.0833µs |
| 실제 잡음 측정 | 256샘플, 약 4.2667µs |
| 매 프레임 추가 무송신 구간 | 261샘플, 4.35µs |
| 기존 CP 포함 프레임 | 16,704샘플, 278.4µs |
| 측정 구간과 프레임을 합친 시간 | 16,965샘플, 282.75µs |

추가 시간은 기존 프레임의 **1.5625%**, 합친 전체 시간의 **약 1.5385%**다.
측정 구간의 송신 에너지는 0이며, 기존 데이터·파일럿·CP 에너지와 측정 비트 수는 유지한다.
추가 시간을 무시하거나 기존 25% 파일럿·보호칸 예산에 숨기지 않는다.
측정과 데이터 구간에서 잡음 전력이 같고 샘플은 독립이라는 통제 가정을 둔다.
잡음 측정용 난수 흐름은 데이터 구간 잡음·데이터·채널 흐름과 분리한다.
같은 시행의 네 방식·A/B·`Eb/N0`에는 기존 대응 원칙에 따라 같은 별도 단위 잡음 실현을
쓰고 생성 측에서만 배율을 적용한다. 데이터 구간 잡음으로 이 샘플을 재사용하지 않는다.

독립 복소 Gaussian 잡음 `L`개에 대해 이 추정치의 평균은 실제 분산과 같고,
분산은 `sigma⁴/L`이다. 따라서 상대 표준편차는 `1/sqrt(L)`이며,
**256샘플에서는 6.25%**다. 매번 오차가 6.25% 이내라는 보장이나 BER의 오차 범위가 아니다.
한 블록 분량의 짧은 추가 시간으로 시작하기 위한 초기 선택이며, BER 최적 길이로 검증한 것은 아니다.

`noise_estimation.py`의 `build_silent_noise_measurement`는 공개 측정 설정·샘플률·지연 상한만 읽는다.
그 결과의 `estimate`에는 정확히 261샘플의 실제 무송신 수신 관측만 전달한다.
앞 5샘플을 제외하고 256샘플의 전력을 평균하며, 데이터 구간까지 붙여서 전달하면 거부한다.
전부 0인 관측에는 0을 반환하며, 수치 바닥값을 임의로 더하지 않는다.
0은 아래의 SVD/LSQR 최소제곱 경로로, 작은 양수는 원래 정규화 항을 유지해 처리한다.

```powershell
python check_noise_estimation.py --output data/noise_estimation_check.json
```

선정한 256샘플과 후속 민감도 후보 512·1,024샘플을 각각 8,192번 진단했다.
256샘플에서 추정 전력/실제 전력의 평균은 약 **1.000456**, 상대 표준편차는
**약 6.231%**로 이론값 6.25%와 일치했다. 별도의 직렬 채널 검사에서는 모든 공개
0~5샘플 지연 탭에 시간 변화를 넣어도 5샘플 대기 뒤 이전 송신 성분이 사라졌다.
구간 길이 검사·복소 전력 기준·무잡음 입력·기존 `Eb/N0` 격자의 배율 관계도 통과했다.
이 진단의 정답 분산은 평가에만 쓰며 수신 추정기 입력이 아니다.
512·1,024샘플은 비교 후보로만 남기고 조건마다 길이를 바꾸지 않는다.

무잡음/잡음 비교는 생성 측에서 같은 데이터·파일럿·채널을 대응시켜 두 입력을 만들고,
각 수신기가 자기 조건의 관측으로 채널 추정부터 데이터 복원까지 따로 실행하는 방식으로 한다.
무잡음 조건에서 구한 채널 추정값을 잡음 조건에 재사용하지 않는다. 깨끗한 수신 신호와
정답 데이터는 평가에만 쓰며 잡음 조건의 수신기에는 전달하지 않는다.
무잡음에서도 채널 추정·복원 오차가 남을 수 있고, 두 BER의 차이를 독립적인
잡음 오류 확률로 해석하지 않는다. 본 결과는 기존대로 동일한 데이터 심볼 기준
`Eb/N0`에서 네 방식의 BER을 비교한다. 보고할 BER의 공통 측정 비트 수는 유지하며,
짧은 예비 진단은 별도로 표시한다. 무잡음/잡음의 원시 데이터 심볼 수치 복원은 아래처럼
검증했으며, 비트 복원·BER 비교는 아직 실행하지 않았다.

### 기본 MMSE의 데이터·잡음·채널 오차 처리 — 2026-11-04

사용자는 **서로 독립인 등확률 16-QAM 데이터, 기존 평균 심볼 에너지 `E_s=1`, 각 수신기의
추정 채널과 측정 잡음 전력**을 사용하는 기본 MMSE에 동의했다. 실제 채널 추정 오차를
수신기에 알려주거나 별도의 오차 공분산 보정을 더하지 않는다. 이는 초기 수신기 설계이며,
잔여 오차가 실제로 0이 되거나 수신기 전체가 통계적으로 최적이라는 가정은 아니다.
설정은 `receiver_equalization_policy.statistical_model`에 기록한다.

데이터 평균은 0, 공분산은 `R_d = E_s*I = I`로 둔다. 16개 유한 신호점을 사용하는
16-QAM 분포를 유지하며 Gaussian 데이터로 바꾸지 않는다. 프레임마다 경험적 에너지를
다시 1로 맞추지도 않는다. 알려진 파일럿은 데이터 공분산에 섞지 않고 추정 채널로
제거한 뒤 데이터 칸만 미지수로 둔다.

```text
r_data = r - H_hat*p
A_hat = H_hat*P_data
lambda = sigma_hat²/E_s = sigma_hat²
(A_hat^H*A_hat + lambda*I)*d_hat = A_hat^H*r_data
```

`sigma_hat²`는 매 프레임 별도 무송신 구간에서 측정한 **복소 AWGN 전력**이다.
`I`는 항등행렬이고 `^H`는 켤레전치다. 모든 방식에 같은 규칙을 쓰되, 기존 TF·DAFT의
블록별 처리와 OTFS의 전체 DD 처리는 유지한다. 위 식은 풀어야 할 문제를 정하는 것이며,
거대한 역행렬을 실제로 만든다는 수치 풀이 선택은 아니다.

[DD-a-OFDM 논문의 식 (43)–(44)](https://arxiv.org/pdf/2508.04253v2)는 추정 채널로
MMSE를 구성한다. [Sionna 공식 `lmmse_matrix` 설명](https://nvlabs.github.io/sionna/v2.2.0/_modules/sionna/phy/mimo/equalization.html)도
평균 0·공분산 `I`인 데이터와 잡음 공분산 `S`를 이용한 선형 MMSE 식을 제시한다.
우리의 데이터 열 선택·파일럿 제거·잡음 전력 측정은 앞서 합의한 설계다.
해당 구현의 수치 풀이 또는 `lmmse_equalizer` 출력 이득 조정을 그대로 채택한 것은 아니다.

MMSE의 계산 모델에서는 `H_hat`를 고정된 추정 채널로 쓰고 잡음 공분산을
`sigma_hat²*I`로 넣는다. 실제 수신 데이터의 잔차는 계속
`(H-H_hat)*(P_data*d+p)+w`이므로, 채널 오차와 남은 파일럿 오차의 영향이 그대로 남는다.
이 전체 잔차가 백색·Gaussian·데이터 독립이라고 주장하지 않으며, 실제 잔차 전력을
정답 채널로 구해 잡음 항에 더하지 않는다. 따라서 이는 **추정 채널을 대입하는 기본 선형
MMSE**이며, 채널 불확실성을 적분한 최적 MMSE나 비선형 16-QAM 검출기는 아니다.
오차 공분산까지 추정하는 수신기는 방법·수치를 정하지 않은 후속 확장으로 둔다.

`mmse_problem.py`의 `build_mmse_problem`에는 추정 채널 기반 데이터 모델,
원래의 수신 격자, 무송신 구간에서 구한 잡음 전력 추정값과 공개 통계·에너지 설정만 전달한다.
파일럿은 한 번만 제거하고, 우변과 정규방정식 연산·목적함수·TF/DAFT 블록별 행렬을 만든다.
OTFS는 12,288개 데이터 미지수의 전체 프레임 연산을 유지하며 큰 DD 행렬을 저장하지 않는다.
잡음 분산이 0이면 그대로 받아들이고 임의의 양수 바닥값을 더하지 않는다. 이때 행렬이
특이해질 수 있으므로, 아래 수치 풀이에서는 별도의 SVD/LSQR 최소제곱 경로를 사용한다.

```powershell
python check_mmse_problem.py --output data/mmse_problem_check.json
```

16-QAM의 평균·에너지와 독립 심볼 공분산을 정확한 신호점 열거로 확인했다.
상수 단일 탭의 해를 식으로 구할 수 있는 수학 검사 8개와, 각 실제 추정기의
A/B-4 입력 연결 검사 8개를 통과했다. 후자는 생성 측에서 잡음을 넣되, MMSE 입력에는
별도 무송신 관측의 측정값만 전달한다. 이 시행의 실제 주입 분산은 평가용 `0.0025`,
수신기가 사용한 측정값은 약 `0.00251493`이었다.

블록별 행렬·우변과 전체 연산의 차이는 최대 약 `7.62e-16`, 정규방정식의
Hermitian·에너지 관계 오차는 약 `4.51e-16` 이하였다. 채널·파일럿 오차와 AWGN이
남는 관계도 약 `8.37e-15` 이내에서 일치했다. 0 채널·0 잡음 입력은 특이한 0 행렬을
그대로 만들며, 수치 바닥값이나 정답 정보로 문제를 바꾸지 않았다.
이 절의 검사는 **입력식 구성과 연결 검증**이다. 이후 아래처럼 데이터 수치 복원도
별도로 구현·검증했다. 표준 출력 이득 처리·QAM 비트 판정도 뒤의 절에 추가했으며,
전체 공통 비트 수의 BER 비교는 아직 실행하지 않았다.

### MMSE 수치 풀이와 정확도 검증 — 2026-11-04

사용자는 **작은 TF·DAFT 블록은 직접 풀고, OTFS 전체 DD 프레임은 CG로 푸는 방식**과
**상대 방정식 잔차 `1e-8`, 최대 반복 1,000회, `1e-10`으로 더 정확히 푼 결과와의 비교**에
동의했다. 무잡음은 별도 최소제곱 문제로 풀고 잡음 전력을 임의로 올리지 않는다.
설정은 `receiver_equalization_policy.numerical_solver`에 기록한다.

| 조건·방식 | 수치 풀이 |
| --- | --- |
| 잡음 전력 양수, OFDM·DD-a-OFDM | 각 슬롯의 128/256개 데이터 미지수를 직접 풀이 |
| 잡음 전력 양수, AFDM | 각 블록의 192개 데이터 미지수를 직접 풀이 |
| 잡음 전력 양수, OTFS | 12,288개 데이터 미지수를 전체 프레임 CG로 풀이 |
| 측정 잡음 전력 0, TF·DAFT | 원래 직사각형 데이터 행렬의 SVD 최소제곱 |
| 측정 잡음 전력 0, OTFS | 전체 프레임의 감쇠 없는 LSQR 최소제곱 |

직접 풀이는 [NumPy의 선형 방정식 풀이](https://numpy.org/doc/2.3/reference/generated/numpy.linalg.solve.html)를
쓰며 역행렬을 만들지 않는다. 잡음 전력이 양수이면 정규행렬에 양수인 항이 더해지므로
Hermitian 양의 정부호 CG 문제를 얻는다. [CG의 공식 조건·잔차 검사 설명](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.cg.html)을
알고리즘 근거로 확인했으며, 구현은 기존 NumPy만 사용하고 SciPy를 설치하거나 사용하지 않는다.
CG는 0에서 시작하고 첫 구현에는 별도 전처리기를 넣지 않는다.
이는 고정된 추정 채널의 같은 MMSE 식을 푸는 계산이며 채널 재추정·파일럿 피드백을 추가하지 않는다.

정규방정식을 `N*d_hat=b`라 하면 모든 방식에 적용하는 기준은
`rho=norm(b-N*d_hat)/norm(b) <= 1e-8`이다. 이는 수치 풀이의 정확도이며,
`norm(r_data-A_hat*d_hat)` 같은 수신 모델 잔차나 채널 추정 오차·BER을 뜻하지 않는다.
직접 풀이도 모든 블록과 전체 프레임의 잔차를 검사한다.
반복 풀이의 수렴은 원래 방정식에 다시 대입한 잔차로 확인하며, 재귀 잔차만 믿고 종료하지 않는다.
우변이 0이면 최소 노름 해 0과 상대 잔차 0을 반환한다.

무잡음에서 양의 정부호 조건을 보장할 수 없는 경우에는 최소 노름 최소제곱 경로로 간다.
작은 블록은 [`numpy.linalg.lstsq(...,rcond=None)`](https://numpy.org/doc/2.3/reference/generated/numpy.linalg.lstsq.html)를
사용한다. 행렬의 수치적 랭크를 판단하는 기본 문턱은 기계 정밀도에 행렬 차원 최대값을 곱한 값이며,
실제 경로 정보를 보고 이 기준을 조절하지 않는다.
큰 OTFS는 [`LSQR`](https://web.stanford.edu/group/SOL/software/lsqr/)의 Golub-Kahan 반복을 사용한다.
0에서 시작해 감쇠 없이 `A_hat`와 `A_hat^H`만 적용하며, 최소 노름 최소제곱 해를 찾는다.
LSQR에도 같은 정규방정식 잔차 기준과 1,000회 안전 상한을 사용한다.
양수인 잡음 전력이 작다는 이유로 0으로 바꾸거나 양수 바닥값을 추가하지 않는다.

`mmse_solver.py`의 `solve_mmse_problem`은 기존 MMSE 입력과 공개 수치 설정만 읽는다.
데이터 칸 순서의 원시 선형 복원값과 수렴 여부·방법·반복 수·잔차를 반환한다.
미수렴이나 분해 실패는 계산 실패로 남기며, `require_converged`를 통과해야 이후 비트 집계에 쓸 수 있다.
실패한 프레임을 통신 오류로 세거나 빼고 BER을 계산하지 않으며, 잡음·채널 정보를 바꿔 성공을 강제하지 않는다.
이 출력은 아래의 공통 MMSE 이득 처리와 Gray 비트 경판정으로 연결한다.

```powershell
python check_mmse_solver.py --output data/mmse_solver_check.json
```

독립적인 작은 행렬의 직접 해와 비교하는 CG·LSQR 검사, 계수가 부족한 최소 노름 해,
0 채널, 작은 양수 잡음 전력, 의도적으로 반복을 1회로 제한한 실패 검사와,
정확히 0인 TF 응답 칸을 갖는 SVD 검사 등 수학 검사 8개를 통과했다.
실제 수신기 검사는 A/B 다섯 단계 × 무잡음·0·20·30 dB × 네 방식의 **80개 조건**이다.
각 조건에 같은 대응 프레임을 사용하되, 무잡음에서도 자기 관측으로 채널을 새로 추정한다.
생성 측의 실제 잡음 분산이나 채널 정답은 복원기에 제공하지 않는다.

직접 풀이는 허용오차에 따라 반복하지 않으므로, 이미 `1e-10`의 전체·블록 잔차까지 만족한

이는 각 설정의 한 프레임을 이용한 수치 안정성 검증이며 전체 BER 측정량이나 신뢰구간 검사가 아니다.

정한 것은 아니었다. 이후 아래처럼 표준 MMSE 이득 처리·Gray 비트 판정을 추가했다.
상대 방정식 잔차가 작다고 복원 심볼의 오차가 항상 그만큼 작다는 보장은 없다.
이후 아래처럼 공통 비트 수·신뢰구간을 포함한 전체 BER 실행을 연결했다.

### 표준 Gray 16-QAM 비트 판정 — 2026-11-04

사용자는 이 단계에 통상적인 절차를 적용하면 된다고 지적했다. 기존에 합의한
**Gray 16-QAM·평균 심볼 에너지 1·비부호화** 조건에 맞는 표준 경판정을 네 방식에
공통 적용한다. 별도의 수신 실험 변수나 조정할 수치는 추가하지 않는다.
설정은 `common_symbol_modulation.gray_cartesian_mapping`과
`receiver_equalization_policy.data_bit_recovery`에 기록한다.

연속된 네 비트는 `[I_MSB,I_LSB,Q_MSB,Q_LSB]` 순서로 한 심볼을 만든다.
I/Q 각 축에서 다음 Gray 라벨을 쓰고, `s=(I+jQ)/sqrt(10)`으로 고정 정규화한다.

| 축의 비트 | 정규화 전 축 값 |
| --- | ---: |
| 00 | −3 |
| 01 | −1 |
| 11 | +1 |
| 10 | +3 |

이는 재현 가능한 일반적인 Cartesian Gray 라벨 규칙이다. 모든 소프트웨어의
라벨 방향이 이 규칙과 같다는 뜻은 아니며, 우리 송수신 양쪽과 네 파형이 같은 규칙을 쓴다.
프레임마다 경험적 전력을 재조절하지 않고 파일럿 위상열·에너지·데이터 칸 순서도 유지한다.
[Gray QAM·평균 전력 정규화 설명](https://www.mathworks.com/help/comm/ref/qammod.html)과
[QAM 비트 경판정 설명](https://www.mathworks.com/help/comm/ref/qamdemod.html)을 확인했다.
해당 라이브러리의 라벨 방향·오류 수 종료 기준·부호화 예제를 그대로 채택한 것은 아니다.

기본 MMSE의 원시 출력에는 자체 이득이 남는다. 추정 데이터 채널을 `A_hat`,
그 채널과 측정 잡음 전력으로 정한 선형 복원 필터를 `G_hat`라 하면,
심볼별 자체 이득은 `g_i=real(diag(G_hat*A_hat))_i`다.
[공식 MMSE 출력 스케일 설명](https://nvlabs.github.io/sionna/v2.2.0/_modules/sionna/phy/mimo/equalization.html)은
`diag(G*H)`를 이용해 출력 크기를 맞춘 뒤 복조하는 형태를 제시한다.
우리 경판정에서는 같은 처리를 다음과 같이 구현한다.

```text
복원값 z_i에 대해, 16개 신호점 중 |z_i-g_i*s|²가 가장 작은 s를 선택
선택한 신호점에 대응하는 Gray 비트 4개를 반환
```

`g_i>0`이면 `z_i/g_i`에 보통의 최근접 신호점 판정을 적용하는 것과 같다.
기준 신호점 쪽에 이득을 곱하면 `g_i=0`에서도 나눗셈이나 임의의 이득 바닥값이 필요 없다.
정확한 거리 동률은 네 비트 정수 라벨이 가장 작은 점을 선택한다.
0 이득에서는 모든 점의 조건부 중심이 같으므로 이 규칙은 `0000`을 반환한다.
정답 데이터를 이용해 동률을 풀거나 이득을 맞추지 않는다.

이득도 각 수신기의 추정 채널과 측정 잡음 전력만으로 계산한다. TF·DAFT는
기존 블록의 데이터 행렬을 그대로 사용한다. OTFS의 현재 데이터 마스크는 모든
도플러 열에서 같은 지연 행을 쓰므로, 유니터리 inverse-Zak 변환에 의해
**전체 DD 자체 이득의 대각값은 대응하는 시간 블록 자체 이득 대각값의 슬롯 평균**과 같다.
이 동치식으로 큰 DD 행렬을 저장하지 않고 같은 이득을 계산한다.
원시 데이터 복원은 기존 전체 프레임 CG/LSQR을 유지하며, 칸 간 간섭이나 시간 변화를 절단하지 않는다.
이득 계산의 동치식은 아래 작은 전체 행렬과의 직접 비교로 검증했다.

`qam16.py`는 공통 비트 매핑·경판정, `mmse_demapping.py`는 추정 자체 이득과
`recover_data_bits`를 구현한다. 수렴한 MMSE 결과만 비트로 바꾸고, 판정 결과를
채널 추정기에 다시 넣지 않는다. 이것은 통상적인 심볼별 경판정이며 잔여 ICI·채널 불확실성이
있는 실제 모델의 최적 공동 ML 비트 검출기라는 주장은 아니다.
추정 이득 자체의 오차·남은 파일럿 및 데이터 간섭은 복원 비트 오류에 남는다.

```powershell
python check_qam16_receiver.py --output data/qam16_receiver_check.json
```

16개 신호점의 비트 왕복과 에너지, 24개 수평·수직 인접 쌍의 Gray 관계를 확인했다.
네 기저의 작은 전체 행렬에 대해 양수/0 잡음 및 전체 랭크·0 채널·랭크 부족을 포함한
이득 검사 24개에서 최대 절대 차이는 약 `3.33e-15` 이하였다.
단일 16-QAM AWGN의 0·5·10 dB에서는 각 524,288비트로
경판정을 검사하고, Gaussian 판정 영역 적분으로 구한 이론 BER과 표본 오차 안에서 일치했다.
이는 QAM 모듈 검사이며 네 파형의 전체 LOS·공통 도플러 보정 기준 실험을 대신하지 않는다.

실제 파일럿 추정기·잡음 측정·MMSE를 사용하는 A/B-4의 20 dB, 총 8개 수신 연결에서는
각각 49,152개 데이터 비트를 복원했다. 이득을 기준 신호점에 적용한 판정과 출력 나눗셈
형태의 판정이 일치했으며, 더 엄격한 `1e-10` MMSE 풀이와도 비트 불일치가 없었다.
이 짧은 프레임의 오류 수는 검증 기록에만 남기며, 전체 공통 비트 수의 BER 곡선·
신뢰구간이나 네 방식의 성능 순위로 해석하지 않는다.

### 고정 비트 수 BER 실행과 95% 신뢰구간

`run_ber_comparison.py`로 프레임 생성부터 공통 Gray 비트 매핑, 네 파형 변환,
채널·AWGN, 각 파일럿 추정기, 잡음 측정, MMSE, 비트 판정과 정확한 오류 집계를 연결했다.
기준 실험과 다중경로 실험은 별도로 실행한다. 결과 폴더는
`data/ber_comparison_2026_11_04`이며, 시작한 실험 묶음의 이름으로 유지한다.

| 실행 | 조건 | 각 방식·조건·점의 측정량 |
| --- | --- | ---: |
| `baseline` | 단일 단위 이득 LOS, 최고점/이탈의 공통 도플러 완전 보정, CP·파일럿 없는 유효 격자 | 10,485,760비트, 160프레임 |
| `multipath` | 기존 CP·파일럿·별도 잡음 측정과 각 추정기, A/B 다섯 잔여 도플러 단계 | 10,485,760비트, 214프레임 |

두 실행 모두 기존 `Eb/N0=0,5,...,30 dB`에 별도 무잡음 참조를 더한다.
무잡음은 유한한 `Eb/N0` 점으로 그래프에 넣지 않는다. 단일 LOS에서는 고정 단위 이득과
완전 공통 주파수 보정 후의 최근접 판정이 이득을 반영한 MMSE 경판정과 같으므로,
실제 잡음 분산을 수신기에 전달하지 않고 파형·에너지·잡음·매핑 기준을 검증한다.
다중경로 실행은 이미 합의한 보정 후 잔여 채널을 생성한다. 최고점과 이탈에서
같은 잔여 프로파일을 다시 서로 다른 도플러 스트레스로 해석하지 않는다.

파일럿 단계에서는 213개 프레임의 49,152비트를 모두 세고, 마지막 프레임에서
16,384비트만 센다. 마지막 프레임도 **모든 데이터 칸에 평소와 같은 무작위 데이터를
보내고 모두 복원**한다. 집계하지 않는 나머지는 알려진 0 패딩으로 바꾸지 않으며,
그 데이터의 간섭이나 자원·에너지를 없애지 않는다. 네 방식에 같은 정보 비트 접두부를 적용한다.
오류 수 조기 종료는 없고, 계산 실패 프레임을 빼서 분모를 채우지도 않는다.

독립 프레임별로 데이터·반사 위상·데이터 구간 잡음·잡음 측정 구간에 별도 PCG64 흐름을 쓴다.
같은 프레임의 네 방식·A/B·잡음 크기·두 기준 시점에는 대응하는 실현을 재사용한다.
루트 seed는 `20261104`, `SeedSequence`의 `spawn_key=(frame_index,role)`를 사용하므로
작업 완료 순서나 프로세스 수가 난수를 바꾸지 않는다. 서로 다른 프레임의 채널을 연속된
하나의 위상 궤적으로 이어 붙이지 않는다.

수신식은 그대로 두고 실행 비용을 줄였다. TF·DAFT의 큰 로컬 문제는 추정 시간 채널의
정확한 희소 역계산과 Schur complement로 같은 데이터 정규방정식을 푼다. 작은 문제는
Cholesky를 쓰며, 무잡음의 전체 랭크를 추정 행렬의 엄격한 대각 우세로 증명할 수 없으면
기존 SVD 최소 노름 경로를 쓴다. 해를 원래 식에 대입한 전체·각 블록 잔차가 기준을 만족해야 한다.
동치 가속 계산의 정확도 검사가 실패하면 **같은 행렬·정규화 항**을 기존 직접 계산으로 다시 푼다.
채널·잡음·사전정보·허용오차를 바꾸는 방식은 사용하지 않는다.
OTFS는 FFT/IFFT가 상쇄되는 정확한 inverse-Zak 형태로 연산하고, 전체 프레임 CG/LSQR은 유지한다.
독립 직렬 채널 검사와 작은 전체 행렬, 기존 비트 복원 연결을 재검증했다.

사용자는 **95% 프레임 기준 신뢰구간**에 동의했다. 프레임 안에서는 같은 채널·추정값을
여러 비트가 공유하므로, 모든 비트를 독립 Bernoulli 시행으로 취급하는 구간을 기본 보고에 쓰지 않는다.
오류가 관측되면 프레임별 `(오류 수 e_i, 측정 비트 n_i)`로
`p=sum(e_i)/sum(n_i)`, `SE=sqrt(G/(G-1)*sum((e_i-p*n_i)^2))/sum(n_i)`를 구하고,
표준정규 임계값을 적용한 95% 구간을 `[0,1]`로 제한한다.
이는 독립 프레임 수가 충분한 경우의 **근사 CR1 구간**이며 정확한 이항 구간이나 동시 신뢰대역은 아니다.
오류가 발생한 프레임 수도 결과에 함께 남긴다.
[프레임을 군집 단위로 취급하는 추론의 근거](https://cameron.econ.ucdavis.edu/research/Cameron_Miller_JHR_2015.pdf)는
군집 간 독립·군집 내부 상관을 허용하는 표준오차 추정이다. 우리 BER 비율에 적용한 식은 그 절편 추정의 형태다.

오류가 0개일 때는 `[0,0]`을 보고하지 않는다. 완전한 `M`개 프레임에서 오류가 하나도 없으면,
프레임에 오류가 하나 이상 생길 확률의 95% 양측 상한 `1-0.025^(1/M)`을 사용한다.
평균 BER은 프레임 오류 확률보다 클 수 없으므로 이를 보수적인 BER 상한으로 쓸 수 있다.
마지막 부분 프레임은 `M`에서 제외한다. 이 값은 프레임 내부 의존을 임의로 허용하므로
독립 비트를 가정한 상한보다 훨씬 넓을 수 있다.
[정확한 이항 한계 설명](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbici.htm)을
프레임 오류 사건에 적용했으며, 비트 독립 상한으로 바꿔 더 정밀해 보이게 하지 않는다.

실행 설정 원본·수치 소스 SHA256·라이브러리 버전·seed·프레임별 오류 수를 저장한다.
완료한 프레임은 중간 파일에 남고, 같은 수치 코드와 저장된 설정으로 `--resume`할 수 있다.
Windows의 순간적인 결과 파일 잠금에는 짧게 재시도하며, 오류 프레임을 정상 데이터로 세지 않는다.
짧은 속도·구현 진단은 `--diagnostic-frames`로 별도 폴더에 저장하고 본 비교와 구분한다.

```powershell
python -m pip install -r requirements.txt -r requirements-ber.txt
python -B check_ber_pipeline.py
python -B run_ber_comparison.py --stage baseline --output data/ber_comparison_2026_11_04/baseline --workers 4
python -B run_ber_comparison.py --stage multipath --output data/ber_comparison_2026_11_04/multipath --workers 12
# 중단한 같은 실행을 이어갈 때 해당 실행 명령 끝에 --resume 추가
python -B plot_ber_comparison.py --baseline data/ber_comparison_2026_11_04/baseline/results.json --multipath data/ber_comparison_2026_11_04/multipath/results.json --output results/ber_2026_11_04
```

그래프의 빈 아래 삼각형은 오류 미관측이다. `1/N` 위치는 로그축 표시를 위한 값이며
추정 BER이나 신뢰 상한을 뜻하지 않는다. 보수적 상한은 결과 표에 실제 값으로 표시한다.
실선은 측정점을 연결하며, 점선 수평선은 오류가 관측된 무잡음 참조를 나타낸다.
결과는 네 파형의 **각 파일럿·추정기·수신기를 포함한 송수신 설계 비교**로 해석한다.

현재 단일 LOS 실행은 최고점·이탈의 모든 점에서 같은 10,485,760비트 측정을 완료했다.
무잡음 오류는 없고, 유한 잡음의 이론값 차이는 최대 약 1.43 프레임 표준오차였다.
3경로 본 실행의 최종 수치는 모든 프레임이 끝난 뒤 아래에 추가한다.

### OFDM BEM 추정 구간의 결정 과정 — 2026-11-04

**검토 중인 BEM 기반 LS의 채널 추정 구간을 한 프레임의 64개 OFDM 블록으로
확정**했다. 구간 결정 당시에는 기저 함수·개수를 후속 검토로 남겼고,
아래 추가 논의에서 DPSS/Slepian 31개를 초기 기저로 정했다. 전체 추정 알고리즘의
충분성은 계속 검증할 항목이다.

| 검토한 범위 | 현재 조건에서의 이점과 제약 |
| --- | --- |
| 한 블록씩 독립 추정 | 국소 모델이 짧아지지만 파일럿이 없는 블록에는 이웃 블록의 정보·보간 또는 별도 모델이 필요함 |
| 한 프레임의 64블록 공동 추정 — 선택 | 프레임의 32개 파일럿 시간 위치를 모아 시간변화 모델을 추정할 수 있으며, 한 프레임 안에서 경로 파라미터를 유지하는 현재 채널 모델과 연결하기 자연스러움 |

선택 과정에서 확인한 수치는 다음과 같다.

- OFDM 유효 블록 256샘플 + CP 5샘플 = 261샘플, 60 MHz에서 **4.35 µs**
- 64블록 = **16,704샘플, CP 포함 278.4 µs**
- TF 파일럿은 시간 인덱스 `0,2,...,62`의 32개 위치와 주파수 128개 위치에 존재하므로,
  프레임 안의 활성 파일럿 관측은 **4,096개**
- 시간 인덱스 `1,3,...,63`에는 직접 파일럿이 없으므로, 한 블록만 독립적으로 보는
  파일럿 기반 추정만으로는 프레임 전체를 처리할 수 없음

현재 채널은 한 프레임 안에서 경로 지연·크기·초기 위상 파라미터를 유지하고,
경로별 도플러가 만드는 결정적 위상 변화는 반영한다. 따라서 프레임 전체의
파일럿으로 하나의 **시간변화 모델**을 추정하고, 각 블록의 실제 샘플 시각에서
이를 평가해 채널을 얻는 방향으로 정했다. 시간축에는 CP 구간도 포함한다.
독립 시행에서는 반사경로의 초기 위상을 다시 뽑으므로, 서로 다른 프레임의
관측을 하나의 연속 채널로 묶지 않는다.

이 결정은 수신기의 **채널 추정 구간**에 관한 것이다. 송신은 기존 256점 OFDM
블록 64개 구성을 사용한다. 이후 별도 결정에서 TF 슬롯별 256칸 처리 범위와
채널 연산을 정했다. 파일럿 자원·에너지 예산과 실제 경로 파라미터를 수신기에 주지 않는
정보 규칙도 유지한다.

긴 구간을 쓰는 데 따른 모델링 부담도 기록한다. 최대 잔여 도플러 크기
46,875 Hz의 경로는 명목 프레임 시간 동안 `46,875 * 278.4e-6 = 13.05`회전한다.
따라서 구간 전체의 채널을 상수로 두는 대신 이 변화를 표현할 기저와 개수가
필요하다. 현재 선택이 최적 길이라는 성능 검증은 아직 없으며, 다음 단계에서
모델 근사 오차·추정식의 식별 가능성과 조건수·파일럿 없는 블록의 오차를 확인한다.
특히 마지막 63번 블록의 추정도 확인한다.

[여러 OFDM 블록에 걸친 BEM 및 LS 추정 연구](https://www.jstage.jst.go.jp/article/transcom/E95.B/10/E95.B_3252/_article/-char/en)는
방법군의 참고 근거다. **64블록이라는 수치는 이번 프로젝트의 프레임·파일럿·채널
설정에 근거한 선택**이며, 참고 논문에서 정한 값을 복사한 것이 아니다.
수신기 구현이나 BER 결과를 새로 얻은 결정은 아니다.

| 다항식 기저 | 짧고 완만한 변화의 간단한 모델이지만, 최대 경로 위상이 약 13회전하는 전체 프레임을 낮은 차수로 표현하기에는 근사 오차가 큼 |
| DFT 격자의 복소지수 기저 | 회전하는 채널과 연결하기 쉽고 이번 파일럿 행렬의 수치 조건도 양호했으나, 격자와 맞지 않는 도플러 및 유한 구간의 경계에서 근사 오차를 확인해야 함 |
| DPSS/Slepian 기저 | 유한 시간 구간과 제한된 도플러 대역을 반영하는 후보이며, 충분한 개수에서는 표현 오차가 작았으나 개수 증가에 따른 잡음 민감도도 검토해야 함 |

근사 편향과 추정 분산의 관계를 설명한다.
[여러 OFDM 블록의 BEM·LS 추정 연구](https://www.jstage.jst.go.jp/article/transcom/E95.B/10/E95.B_3252/_article/-char/en)도
DPSS 계열을 사용한다. 이 문헌 결과를 우리 실험의 BER 우열로 간주하지 않는다.

예비 수치 검토는 `review_bem_basis.py`와 `data/bem_basis_review.json`에 남겼다.
추가 라이브러리 없이 기존 NumPy로 실행한다.

  `−46,875..+46,875 Hz`의 합성 단일 경로 시간함수 401개를 평가했다.

#### 29·30·31개 추가 비교와 초기값 결정

사용자가 30개를 제외한 이유를 질문해 같은 조건에서 DPSS 30개도 추가 계산했다.
처음의 홀수 후보는 복소지수 기저를 `-Q..0..+Q`의 정수 주파수 쌍으로 구성한
비교와 개수를 맞춘 것이었다. **DPSS 함수 수에는 홀수 제약이 없으며, 30개도 유효하다.**
[DPSS 공식 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.windows.dpss.html)의
`Kmax`는 반환할 함수 개수다. 이 검토는 SciPy 설치 없이 기존 NumPy 구현으로 수행했다.

29·30·31개의 최대 상대 L2 근사 오차는 각각 약 **9.91%·3.92%·1.46%**다.
백색 관측 잡음만 가정한 이상적 LS의 채널 MSE 전달 지표는 29개를 기준으로
각각 **1·1.85·3.22배**다. 이 지표는 알려진 파일럿 성분의 관측행렬에 대한
잡음 민감도이며, 실제 수신기의 채널 추정 오차나 BER 비율은 아니다.

사용자와 **DPSS 31개를 초기값으로 사용하기로 합의**했다. 최대 잔여 도플러까지
포함하는 비교에서 채널 시간변화의 근사 부족을 줄이는 데 우선순위를 둔 판단이다.
30개를 제외하는 수학적 조건이나 31개가 최적이라는 검증 결과는 없다.
잡음 민감도가 커지는 단점이 있으므로 실제 파일럿 기반 채널 추정에서
미지 데이터의 ICI와 AWGN을 포함해 29·30개와 비교해야 한다.
설정의 `basis_type`은 `DPSS_Slepian`, `basis_function_count`는 `31`로 반영했다.
이는 초기 기저의 결정이며, BEM 기반 LS 전체 수신기는 파일럿 관측 모델과
추정법의 적합성 검증이 남은 후보 상태로 유지한다. 이후 사용자가 지연 범위는
이미 정해진 것과 같다고 지적해, 기존 최대 초과 지연·CP에 맞춘 `0..5`샘플을
공통 수신기 탐색 범위로 명시하고 다음 순수 LS 진단을 진행했다.

### OFDM BEM 계수의 LS 추정식과 예비 검증 — 2026-11-04

사용자가 파일럿으로 BEM 계수를 구하는 단계를 진행하기로 해, **순수 LS를
기준 시제품으로 구현**했다. 실제 파일럿 관측에는 데이터 간섭이 섞이므로,
이 구현을 최종 수신기로 채택하기 전에 그 영향을 확인한다.

수신기에 주는 지연 정보는 네 방식 공통으로 **LOS 대비 초과 지연 0~5샘플**이다.
60 MHz의 정렬된 정수 지연 모델과 CP 5샘플에 맞춘 범위다. 수신기는 후보
`0,1,2,3,4,5`를 고려하고, 실제 경로의 위치 `0,2,5`는 전달받지 않는다.
공통 `P=3` 정보는 유지하지만 이 밀집 LS 시제품에서는 세 경로를 강제로 골라내지 않는다.
분수 지연·시간 정렬 오차·더 넓은 범위는 후속 확장이다.

각 지연 후보 `l`의 시간변화는 다음처럼 표현한다.

`h_l[n] ≈ Σ(q=0..30) b_q[n] c_lq`, `l=0..5`

`b_q[n]`은 합의한 고정 DPSS이며, `c_lq`가 파일럿으로 구할 복소 계수다.
따라서 미지수는 **6개 지연 후보 × 31개 함수 = 186개**다. 알려진 파일럿만
담은 송신 신호에 각 지연과 기저 함수를 적용하고, 실제 블록별 CP 제거·FFT를
거쳐 파일럿 위치를 뽑으면 **4,096×186 관측행렬 `A_p`**를 얻는다.
프레임 전체 FFT 하나를 쓰는 것이 아니며, 실제 시간축에는 CP가 포함된다.

`y_p = A_p c + i_data + e_BEM + w_p`

`c_hat = argmin_c ||y_p − A_p c||² = A_p† y_p`

여기서 `i_data`는 도플러 때문에 데이터가 파일럿 위치에 섞이는 성분,
`e_BEM`은 기저의 근사 오차, `w_p`는 수신 잡음이다. 순수 LS는 이 항들을
관측 오차로 남긴다. **실제 데이터 정답으로 간섭을 제거하지 않으며, 데이터 간섭이
백색·가우시안·채널 독립이라는 가정도 추가하지 않았다.** 가중치·정규화 항이나
판정 피드백을 넣는 방식은 아직 선택하지 않았다. 계산은 직접 SVD 풀이를 사용하며,
잡음 분산이나 실제 활성 경로 위치를 입력받지 않는다.

`ofdm_bem.py`가 수신기 시제품이고, `check_ofdm_bem_ls.py`는 독립 직렬 채널과
오차 평가를 담당한다. 수신기 생성기에는 `channel_model`을 제거한 공개 설정만 넘긴다.
DPSS 생성은 기존 검증 함수를 그대로 `bem_basis.py`로 옮겨 공유한다.
[여러 블록의 DPSS BEM 및 LS 연구](https://www.jstage.jst.go.jp/article/transcom/E95.B/10/E95.B_3252/_article/-char/en)는
방법군의 근거이며, 이 식과 현재 파일럿 배치에서의 구현은 우리 설정에 맞춘 시제품이다.

```powershell
python check_ofdm_bem_ls.py --trials 16 --output data/ofdm_bem_ls_review.json
python check_ofdm_bem_ls.py --trials 16 --basis-count 29 --output data/ofdm_bem_ls_29_review.json
python check_ofdm_bem_ls.py --trials 16 --basis-count 30 --output data/ofdm_bem_ls_30_review.json
```

16프레임은 구현과 경향 확인용 진단 규모다. 기존 BER의 고정 비트 수와 종료 기준을
바꾼 것이 아니다. 진단의 데이터·초기 위상·잡음에는 `SeedSequence(20261104)`에서
분리한 PCG64 흐름을 사용하고, A/B·기저 수·잡음 크기 사이에 같은 실현을 대응시킨다.
파일럿은 기존 고정 위상열을 유지한다. 모든 `0:5:30 dB` 점에서 데이터와 AWGN을
포함했으며, 등화·비트 검출은 수행하지 않았다.

검증에서 관측행렬은 rank **186/186**, 조건수 약 **14.55**였다.
별도 직렬 시간변화 채널로 만든 정확한 BEM 신호의 계수 복원 상대 오차는
약 `3.08e-15`였다. 정적인 A에서는 데이터의 파일럿 유입이 수치 오차 수준이었으며,
B에서는 실제 데이터 유입과 추정 오차가 생겼다.

16프레임의 선형 값을 평균하고 dB로 표시했다. 낮을수록 좋으며 BER이 아니다.

| --- | ---: | ---: |

최대 도플러 B-4에서 29·30·31개 기저의 전체 채널 NMSE는 각각
**−21.19·−24.46·−26.42 dB**였다. 다만 B-3에서는 각각
**−35.49·−32.94·−32.29 dB**로, 기저 수를 늘리는 것이 모든 조건에서 유리하지는 않았다.
합의한 초기 31개는 유지하고, 조건별 정답 도플러에 맞춰 기저 수를 바꾸지 않는다.

**순수 LS 계산은 동작하며, 데이터 간섭과 프레임 끝의 추정 오차를 확인했다.**
특히 31개의 B-4에서 잡음이 없어도 마지막 블록 NMSE가 약 −9.82 dB였고,
`Eb/N0=20 dB`에서는 약 −9.06 dB였다. 함수의 최적 근사 오차가 작다는 사실만으로
실제 파일럿 추정이 충분하다고 판단할 수 없다. 다만 사용자가 강조한 목표는
동일한 `Eb/N0`에서 네 방식의 **BER 비교**이며, 채널 추정 NMSE는 중간 점검과
원인 분석용이다. 추정 오차를 모두 줄이거나 OFDM만 계속 개선해야 다음 단계로
갈 수 있는 것은 아니다. 현재 BEM-LS는 한계를 기록한 초기 후보로 유지하고,
다른 방식의 수신기를 구체화한다. 구현 오류는 고치되 추정법 자체의 한계로 남는
오차는 최종 BER에 반영해 비교한다. 새로운 OFDM 보정 방식은 추가하지 않았다.
공통 도플러 상한 정보는 이후 ±46.875 kHz로 정했고 OTFS 초기 추정법도 선정·검증했다.
DD-a-OFDM 추정기와 네 방식의 추정 채널 연산도 구현·예비 검증했다.
파일럿 제거·데이터 미지수 구성도 구현했다. 공통 잡음 측정과의 연결,
기본 MMSE 수치 복원과 표준 이득 처리·비트 판정도 위처럼 구현·검증했으며, 전체 BER 실행에도 연결했다.

### 추후 비교 발표에 포함할 BEM 설명

네 가지 송수신 방식의 비교 발표를 준비할 때 **BEM(Basis Expansion Model)**을
짧게 소개한다. 시간에 따라 변하는 채널을 소수의 기본 함수와 계수의 합으로
근사한다는 개념과, 파일럿으로 계수를 LS 추정해 ICI를 포함한 TF 채널행렬을
구성한 뒤 선형 MMSE 등화에 활용하는 후보 흐름을 설명한다.
[BEM 기반 LS 추정과 선형 MMSE 등화 연구](https://www.jstage.jst.go.jp/article/transcom/E95.B/10/E95.B_3252/_article/-char/en)를 참고한다.
현재 BEM 기반 LS는 OFDM 채널 추정의 **검토 후보**이며, 한 프레임 64블록의
추정 구간과 초기 DPSS/Slepian 31개 기저는 정했다. 순수 LS 관측식과 예비 채널 추정
오차도 검토했으며, 데이터 간섭 처리·프레임 끝 정확도·등화·BER 검증은 남아 있다.
위의 결정 과정도 발표 준비 시 함께 참고한다.
이는 나중에 발표에 넣을 내용의 메모이며, 지금 발표 파일을 제작하는 작업은 아니다.

## 파일럿 비교 원칙

네 방식의 파일럿 위치는 각 방식에 맞게 둘 수 있지만, 프레임에서
**파일럿과 그 때문에 비워 두는 보호칸이 차지하는 비중**은 동일하게 맞춘다.
파일럿 신호에 할당한 **총 에너지**도 동일하게 맞춘다. OFDM과 DD-a-OFDM은
같은 시간–주파수 파일럿 위치를 사용하되, DD-a-OFDM의 수신기는 이를 DD
영역에서 처리한다. AFDM은 고유한 DAFT 영역, OTFS는 지연–도플러 영역의
파일럿 배치를 사용한다. 파일럿 보호칸은 앞서 0개로 정한 주파수 격자의
양끝 보호칸과 별개의 자원이다. 아래의 공통 비율·총 에너지 예산은 확정했으며,
네 방식의 배치와 알려진 고정 파일럿 값·방식 내 균등 에너지 배분은 아래와 같이 정했다.
각 추정기의 수치 설정과 실제 추정 성능은 계속 논의·검증한다.
첫 단일경로 기준 실험의 공통
도플러 보정은 완전한 주파수 정보로 수행하므로, 도플러 획득용 프리앰블을
채택한 것은 아니다. 실제 도플러 추정·추적 방식은 후속 논의 대상으로 남긴다.

### 합의한 공통 파일럿 예산

다음 수치를 **후속 첫 파일럿 기반 3경로 비교의 초기 예산으로 합의**했다.
기준 단위는 보호구간을 제외한 공통 **256×64 = 16,384칸**의 유효 격자다.
구체적인 배치와 누설·추정 성능의 충분성 검증은 계속 진행할 항목이다.

| 항목 | 합의한 초기 예산 |
| --- | ---: |
| 파일럿 + 파일럿 보호·예약칸 | 25% = 4,096칸 |
| 데이터 | 75% = 12,288칸 |
| 총 파일럿 에너지 | 네 방식 모두 `E_p = 4,096 E_s` |
| 데이터 심볼 평균 에너지 | 기존 `E_s = 1` 유지 |

**파일럿과 보호칸을 합친 비용**, **총 파일럿 에너지**를 프레임 단위로 맞춘다.
OFDM과 DD-a-OFDM은 TF 파일럿 위치·값·에너지 배분을 같게 두고, AFDM은 DAFT,
OTFS는 DD 영역에서 배치한다. 서로 다른 기저의 파일럿 좌표까지 같게 만들지는
않는다. 실제로 쓰는 파일럿 수가 `N_p`라면 균등 배분 시 개별 파일럿 에너지는
`E_p/N_p`다. 파일럿 수가 다른 방식은 개별 파일럿의 세기도 달라진다.
결과에는 실제 파일럿 수·보호/예약칸 수·데이터 수·총 파일럿 에너지도 따로 기록한다.

25%의 근거는 조건부 자원 계산이다. [AFDM 논문의 embedded pilot 배치식](https://arxiv.org/pdf/2204.12798#page=24)을
매 256점 블록에 적용하고 현재 설계 범위 `l_max=5`, `alpha_max=1`, `xi_nu=1`을
사용하면 파일럿과 보호칸은 `2*(5+1)*(2*(1+1)+1)-1 = 59`칸, 약 **23.05%**다.
이를 64칸, 즉 25%로 올려 잡아 초기 예산으로 정했다. 블록마다 논문형 단일 파일럿을
넣고 보호칸을 5칸 확장한 배치를 아래와 같이 선택했다.
59칸이 모든 AFDM 배치의 최소값이라는 뜻은 아니다.
현재 분수 도플러 여유에서 실제 누설과 추정 성능도 검증해야 한다.

합의한 에너지 예산에서는 데이터의 기대 에너지 12,288과 파일럿 에너지 4,096의
합이 16,384가 되어, 유효 격자의 평균 에너지 규모를 맞추기 쉽다. 모두 정규화된
시뮬레이션 단위이며, 개별 프레임을 측정해 다시 전력을 맞추지는 않는다.
CP/CPP의 샘플 수·에너지는 따로 계산한다.

다중경로의 공통 LOS 완전 보정과 잔여 도플러 범위는 정했으며,
네 방식의 첫 배치와 알려진 파일럿 값·균등 에너지 배분도 아래와 같이 정했다.
피크 전력 조건과 수신기 성능 검증은 계속 검토할 항목이다.
보호칸을 포함한 25%가 각 방식의 최적 비율이거나 모든 미래 도플러 조건에서
충분하다고 검증한 것은 아니다. 고정 정보 비트 수 조건은 유지하며,
마지막 프레임의 데이터·패딩 집계는 계속 설계할 항목이다.

이 예산에서 16-QAM 데이터를 모두 채운 프레임의 데이터 비트 수는
`12,288 × 4 = 49,152`다. 기존 측정량 10,485,760비트를 유지하면 완전한 데이터
프레임 213개와 나머지 16,384비트가 필요하므로, 예산상 214번째 프레임까지
필요하다. 이는 자원 계산이며, 실제 마지막 프레임의 배치·패딩·측정 처리는
아직 정하지 않았다. 파일럿·보호칸·패딩을 BER의 정보 비트 수에 포함하지 않는다.

### OFDM과 DD-a-OFDM의 공통 TF 파일럿 배치

두 방식은 **주파수 2칸마다 × 시간 2블록마다** 같은 위치에 파일럿을 둔다.
재현을 위한 좌표 원점은 0 기반 배열의 `(주파수 0, 시간 0)`으로 둔다.
즉 주파수 인덱스 `0,2,...,254`와 시간 인덱스 `0,2,...,62`의 교차점이 파일럿이다.
나머지 TF 칸에는 데이터를 넣는다. A 및 모든 B 단계에서 같은 배치를 사용한다.

| 항목 | 두 방식 각각의 프레임당 값 |
| --- | ---: |
| 파일럿 주파수 행 × 시간 열 | 128 × 32 |
| 활성 파일럿 | 4,096칸 |
| 파일럿 전용 보호·예약칸 | 0칸 |
| 데이터 | 12,288칸 |
| 파일럿 + 파일럿 보호·예약칸 비중 | 25% |
| 총 파일럿 에너지 | 기존 `4,096 E_s` 유지 |

CP 5샘플은 별도의 시간 보호구간으로 유지한다. 두 방식은 같은 고정 QPSK
파일럿 값을 쓰며, 각 활성 파일럿의 에너지는 균등하게 `1 E_s`로 둔다.

파일럿의 주파수 간격은 468.75 kHz, CP 포함 시간 간격은 8.7 µs다.
[DD-a-OFDM 논문의 Remark 1](https://arxiv.org/pdf/2508.04253v2#page=6)의
균일 TF 샘플링 조건을 적용하면 기본 지연 주기는 약 2.133 µs,
대칭 도플러 범위는 약 ±57.47 kHz다. 현재 초과 지연 0·2·5샘플과
최대 잔여 도플러 ±46.875 kHz는 이 기본 범위 안에 있다.
이는 자원·기본 샘플링 범위 확인이며, 분수 도플러의 누설·실제 추정 오차·BER까지
검증한 것은 아니다. 네 방식의 실제 추정 성능은 계속 확인한다.

### AFDM과 OTFS의 파일럿·보호·예약칸 배치

AFDM은 매 256칸 DAFT 블록에서 파일럿 인덱스를 0으로 둔다. 순환 방향으로
앞 31칸(`225..255`), 뒤 32칸(`1..32`)은 0으로 비우고,
나머지 `33..224`의 192칸에 데이터를 넣는다. 이를 64개 블록에 반복한다.
[AFDM embedded pilot 방식](https://arxiv.org/pdf/2204.12798#page=19)을 바탕으로
현재의 59칸 계산보다 보호칸을 5칸 늘린 구성이다. 분수 도플러의 꼬리 누설은
유지되므로, 채널 추정기에서 실제 영향을 검증해야 한다.

OTFS는 0 기반 `(지연 128, 도플러 32)`에 파일럿 1칸을 둔다.
지연 `96..159`의 64칸 × 도플러 `0..63`의 전체 64칸을 비데이터 영역으로
예약하고, 파일럿을 제외한 나머지는 0으로 둔다. 이 중 지연 `123..133`의
11개 행이 [분수 도플러 full-guard 방식, 식 (7)](https://arxiv.org/pdf/1808.08360#page=4)의
`(2*5+1)*64 = 704`칸에 해당한다. 파일럿을 제외한 기본 보호칸은 703개이며,
나머지 3,392칸은 같은 25% 비교 조건을 맞추는 추가 예약칸이다.
25% 전체가 OTFS에 필요한 최소 보호영역이라는 뜻은 아니다.

| 방식 | 활성 파일럿 | 보호칸 | 추가 예약칸 | 데이터 | 활성 파일럿 한 칸의 에너지 |
| --- | ---: | ---: | ---: | ---: | ---: |
| OFDM | 4,096 | 0 | 0 | 12,288 | `1 E_s` |
| DD-a-OFDM | 4,096 | 0 | 0 | 12,288 | `1 E_s` |
| AFDM | 64 | 4,032 | 0 | 12,288 | `64 E_s` |
| OTFS | 1 | 703 | 3,392 | 12,288 | `4,096 E_s` |

네 방식 모두 **파일럿 + 보호 + 예약칸은 4,096칸**, **총 파일럿 에너지는
`4,096 E_s`**다. 방식 안에서는 모든 활성 파일럿에 에너지를 균등하게 나눈다.
OTFS는 파일럿 하나이므로 에너지가 4,096이며, `E_s=1`에서 복소 진폭 크기는
64로 정해지며, 위상은 0으로 두어 파일럿 값을 `64+0j`로 선택했다.

### 합의한 고정 파일럿 값과 비교 해석

기본 위상값은 `q ∈ {1, j, −1, −j}`의 QPSK 값으로 둔다.
OFDM/DD-a-OFDM은 4,096개 고정 위상값을 같은 순서로 사용하고,
AFDM은 이 기본 위상열의 앞 64개를 가져와 크기만 8배로 보낸다.
따라서 각 방식의 알려진 파일럿은 다음과 같다.

| 방식 | 알려진 파일럿 값 | 파일럿 하나의 에너지 |
| --- | --- | ---: |
| OFDM·DD-a-OFDM | `q` | `1 E_s` |
| AFDM | `8q` | `64 E_s` |
| OTFS | `64+0j` | `4,096 E_s` |

위상열은 독립 로컬 RNG(`NumPy PCG64`, 시드 `20261103`)로 한 번 정해지는
재현 가능한 값이다. 프레임·독립 시행·`Eb/N0`·도플러 단계·궤도 시점에 걸쳐
같은 값을 재사용한다. 데이터와 무작위 채널 위상을 만드는 난수열은 소모하지 않는다.
시퀀스의 생성 규칙과 해시를 `scenario.json`에 기록했다.
송수신기가 아는 파일럿 값이며, 실제 채널 지연·경로별 도플러·이득의 정답을
수신기에 주는 것은 아니다. 데이터 변조는 기존 비부호화 Gray 16-QAM을 유지한다.

현재 비교는 **같은 자원·에너지 예산에서 각 파일럿 기반 송수신 설계의 BER을
비교**하는 것이다. 파형별 파일럿 수·기저·채널 추정·등화 방식의 영향도 결과에
포함된다. 총량을 맞췄다는 이유로 모든 BER 차이를 파형 자체에만 귀속하지 않는다.
이 고정 시퀀스는 합의한 초기 설계이며, 최적화된 파일럿이라는 주장은 하지 않는다.

유니터리 변환은 파일럿 성분의 에너지를 보존하므로, 이 동등성은
**CP를 붙이기 전 실제 유효 송신 시간 신호의 파일럿 에너지**에도 적용된다.
CP로 복사하는 에너지는 별도 집계하며, CP까지 합친 총 파일럿 성분 에너지가
자동으로 같아진다는 의미는 아니다. 이는 기존 CP 에너지 집계 원칙을 유지한 것이다.

### 배치 구현 및 검증 범위

`pilot_layouts.py`의 `build_masks`는 네 방식의 파일럿·보호·예약·데이터 마스크를 만든다.
`known_pilot_symbols`는 위의 합의한 고정 파일럿을 만든다. `build_grid`는
이를 기본값으로 사용해 호출자의 데이터를 각자의 기저에 배치한다.
검증용 파일럿을 명시적으로 전달할 수도 있지만 총에너지 4,096 조건을 확인하며,
값이나 진폭을 자동으로 바꾸지 않는다. 각 영역의 심볼은 열 우선(`order="F"`) 순서로 채운다.

```powershell
python check_pilot_layouts.py
```

합의한 고정 파일럿으로 재현성·기본 위상열 재사용·균등 에너지·칸 수·영역 분리·변환 왕복·실제 유효 송신 시간 신호의
에너지를 확인했다. 네 방식 모두 파일럿 에너지가 4,096이며,
변환 왕복의 최대 상대 오차는 약 `4.56e-16`이다.
현재 CP·정수 지연과 합의한 모든 잔여 도플러 단계에서 OTFS의 데이터 성분이
파일럿 관측 영역으로 새는 상대 노름은 약 `5.35e-17`이었다.
이 검사는 합의한 고정 파일럿 값을 사용한다.
AFDM의 분수 도플러 추정 누설, 네 방식의 채널 추정·등화·BER은 이 검사에 포함하지 않는다.

## 도플러 비교 계획

먼저 공통 도플러를 완전히 보정한 LOS 단일경로 + AWGN 기준 실험에서 네
파형의 BER을 비교한다. 기존에 정한 저·고도플러 두 시점은 궤도 기반 입력과
후속 비교를 위한 참조로 보존한다. 첫 기준 실험에서는 두 시점의 보정 후
잔여 공통 도플러가 모두 0 Hz이므로, 이를 서로 다른 도플러 스트레스 조건으로
해석하지 않는다. 두 시점을 모두 실행한다면 보정 일관성을 확인하는 용도다.
네 파형에는 동일한 수신 `Eb/N0`를 적용한다. 고도만을 기준으로 도플러 값을
가정하지 않고, 선택할 시점의 궤도에서 도플러를 계산한다. 따라서 우리가 정할 것은 두
대표 시각의 선택 기준이며, 도플러 수치는 임의로 정하지 않는다. 현재 통과
초안에서는 최고 고도각 시점(07:46:50.803 UTC)을 저도플러 조건으로,
고도각 10°의 이탈 시점(07:51:02.674 UTC)을 고도플러 조건으로 정했다.
첫 단일경로 기준 실험의 수신기는 이 공통 도플러를 완전히 보정한다.

후속 3경로 실험은 다음의 **A/B 통제 비교**로 정했다. B는 지연도 포함한다.

| 항목 | A: 정적 다중경로 | B: 지연 + 경로별 도플러 |
| --- | --- | --- |
| 경로·초과 지연·상대 전력 | 기존 3경로, 0·2·5샘플, 0·−10·−15 dB | A와 동일 |
| 공통 LOS 도플러 | 궤도에서 계산해 적용한 뒤 완전히 보정 | A와 동일 |
| 보정 후 경로별 도플러 | 세 경로 모두 0 Hz | LOS는 0 Hz, 반사경로의 차이는 단계적으로 증가 |
| 초기 위상·정규화·비트 수·자원/에너지 예산 | 기존 공통 조건 | 같은 시행의 A 및 네 방식과 동일 |

B는 실제 반사환경을 복원한 값이 아닌 **합성 도플러 민감도 실험**이다.
위성 궤도와 수신국 좌표만으로 반사경로 도플러를 확정하지 않는다.
최대 잔여 도플러 크기 `d = max_p |delta_f_p|`를 공통 부반송파 간격
`Delta_f = 234,375 Hz`로 나눈 비율 `epsilon = d/Delta_f`를 사용해 다음을 정했다.

| 조건 | 최대 잔여 도플러 / 부반송파 간격 | 최대 잔여 도플러 `d` |
| --- | ---: | ---: |
| A | 0% | 0 Hz |
| B-1 | 1% | 2,343.75 Hz |
| B-2 | 5% | 11,718.75 Hz |
| B-3 | 10% | 23,437.5 Hz |
| B-4 | 20% | 46,875 Hz |

A를 포함해 총 5개 초기 탐색 조건이다. 이 수치는 합의한 통제 실험용 선택이며,
실제 Starlink 반사경로 측정값이나 표준에서 정한 범위가 아니다.
`d`는 LOS 대비 최대 절댓값이며, 경로 전체의 양 끝 차이인 도플러 확산 폭
`max(delta_f_p)-min(delta_f_p)`과 구분한다. 각 단계에서 경로 순서
`[LOS, 반사 1, 반사 2]`의 잔여 도플러를 **`[0, +d, -d]`**로 정했다.

| 조건 | LOS | 반사 1: 지연 2샘플, −10 dB | 반사 2: 지연 5샘플, −15 dB |
| --- | ---: | ---: | ---: |
| A | 0 Hz | 0 Hz | 0 Hz |
| B-1 | 0 Hz | +2,343.75 Hz | −2,343.75 Hz |
| B-2 | 0 Hz | +11,718.75 Hz | −11,718.75 Hz |
| B-3 | 0 Hz | +23,437.5 Hz | −23,437.5 Hz |
| B-4 | 0 Hz | +46,875 Hz | −46,875 Hz |

반사 1은 양수, 반사 2는 음수로 모든 단계·시행·방식에서 유지한다.
이 배치의 전체 도플러 확산 폭은 `2d`이며, B-4에서는 93,750 Hz다.
기존 명시적 경로 프로파일은 A의 추가 도플러 0 Hz를 유지한다.
B의 경로별 벡터도 `scenario.json`에 확정값으로 기록했지만, 채널 생성기와
네 방식의 BER 실험은 아직 구현·실행한 것이 아니다.
도플러를 정수 DD 칸으로 반올림하지 않고 Hz 값을 그대로 사용한다.
공통 주파수의 정답만 보정에 제공하며, 실제 경로 지연·추가 도플러·복소 이득은
파일럿으로 추정한다. 공통 경로 수 사전정보 `P=3`은 유지한다.
초기 위상과 경로 크기는 같은 시행의 A/B 및 모든 단계에서 재사용하지만, B의
경로별 도플러가 만드는 시간에 따른 위상 변화는 유지한다. 최종 파일럿 배치와
수신 설정도 단계마다 임의로 바꾸지 않으며, 적응 규칙이 필요하면 별도로 함께 정한다.
공통 도플러 보정 오차는 이 A/B에 포함하지 않는 별도 미선택 확장이다.
동일한 잔여 프로파일이라면 최고점·이탈 시점은 보정 후 같은 조건이므로,
B의 도플러 단계들이 새로운 비교 조건이 된다. 이 계획의 BER 실험은 아직 실행하지 않았다.

현재 시나리오 초안의 통과를 기준으로 경사거리의 1초 중앙차분과
`f_D ≈ -f_c (dR/dt)/c`를 적용하면, 고도각 10°의 진입 시점은 약 +260.9 kHz,
선택한 최고 고도각 시점은 약 +0.5 kHz, 최근접 시점은 약 0 kHz,
선택한 이탈 시점은 약 -261.0 kHz다.
이는 제공된 OMM 궤도와 지상국 좌표, 공통 대표 반송파 11.7 GHz에서
계산한 예측값이며, 실제 송신 신호를 측정한 값은 아니다. 통과 날짜·최소
고도각 자체는 아직 시나리오 초안이므로 변경하면 시각과 도플러를 다시 계산한다.

## 확정한 실험 목적

OFDM, AFDM, OTFS, DD-a-OFDM 네 송수신 방식의 BER을 비교한다.
BER 비교 축은 수신 `Eb/N0`이며, 예비 탐색 범위와 간격은 아래에 정했다.

결과는 **가로축: 수신 데이터 심볼 기준 `Eb/N0`(dB), 세로축: BER**인 곡선으로
비교한다. `Eb/N0`는 바꿔가며 넣는 신호·잡음 조건이고 BER이 측정 결과다.
같은 `Eb/N0`에서 BER이 낮은 방식을 비교하며, 같은 곡선에서 목표 BER에 필요한

에너지 집계 조건을 반영해야 하므로 두 값을 같은 이름으로 기록하지 않는다.
[SNR과 Eb/N0의 변환](https://www.mathworks.com/help/comm/ref/convertsnr.html)도
변조 차수·부호율·샘플링 조건을 구분한다.

## 확정한 링크 방향과 대역

성균관대 지상국은 수신만 하며, 위성에서 지상국으로 오는 Ku 다운링크만
비교한다. Ku는 사용할 주파수 대역이고, 신호가 실제 차지하는 대역폭은
별도로 정한다. 네 방식의 공통 반송파 주파수는 11.7 GHz로 정했다.
이는 BER 비교를 위한 Ku 대역 대표값이며, STARLINK-5285가 해당 통과에서
실제로 사용한 채널 중심이라는 주장은 아니다. 명목 격자 대역폭은 아래와 같이
정했다. 첫 BER 비교에서는 가장자리 보호칸과 중앙 DC 빈 칸을 모두 두지 않는다.
실제 스펙트럼 점유 대역폭은 아직 정하지 않았다.

## 확정한 심볼 변조 방식

OFDM, AFDM, OTFS, DD-a-OFDM 모두 같은 16-QAM 심볼을 사용한다. 한 심볼에
4비트를 담는다. 네 방식에 넣는 데이터 심볼의 **평균 심볼 에너지는
`E_s = E[|s|²] = 1`**로 정규화한다. 이는 같은 크기 기준의 심볼로 네 파형을
비교하기 위한 상대적인 에너지 단위이며, 실제 송신전력을 1 W로 정한 것은 아니다.

정규화는 등확률의 16개 신호점 전체에 대한 평균을 기준으로 한 고정 배율이다.
각 심볼의 에너지가 모두 1이라는 뜻이나, 무작위 데이터 프레임마다 순간 평균을
다시 1로 맞춘다는 뜻은 아니다. 예를 들어 일반적인 정사각형 16-QAM에서
`I, Q ∈ {−3, −1, 1, 3}`이면 정규화 전 평균 에너지는 10이므로,
`s = (I + jQ) / √10`으로 평균 심볼 에너지를 1로 맞출 수 있다.

비트-심볼 매핑은 네 방식 모두 동일한 **Gray 매핑**으로 정했다. 정사각형
16-QAM의 수평·수직으로 이웃한 신호점끼리 1비트만 다르게 배치하여,
가까운 점으로 잘못 판단했을 때 발생하는 비트 오류를 줄인다. 오류 정정
부호화는 계속 적용하지 않는다.

`E_b`는 위 잡음 모델 절의 데이터 심볼 기준으로 정의하며, 이에 따른 심볼
기준 잡음 분산은 계산으로 정해진다. 파형 변환은 위의 유니터리 정규화로
통일하고, 첫 샘플링 격자는 60 MHz로 정했다. 필터와 파일럿 에너지 및
후속 실험의 샘플링 변경에 따른 신호·잡음 배율은 별도로 논의한다.
지금까지 네 파형에 넣을 데이터 심볼의 변조 방식·평균 에너지·비트 매핑을
공통으로 정했다.

## 수신 Eb/N0 탐색 계획

첫 BER 비교에서는 네 파형 모두에 같은 수신 `Eb/N0` 값 0, 5, 10, 15, 20,
25, 30 dB를 적용해 넓은 구간을 먼저 탐색한다. 이는 적은 측정 지점으로
BER 변화 구간을 찾기 위한 예비 범위이며, STARLINK-5285에서 측정하거나
링크 예산으로 계산한 SNR 범위가 아니다. 예비 결과에서 BER이 변하거나
파형 차이가 나타나는 구간을 골라 1~2 dB 간격으로 다시 측정한다. 정확한
세부 구간과 간격은 예비 결과를 보고 결정하고, 필요하면 시작·끝값도 확장한다.

## BER 측정량과 종료 기준

각 `Eb/N0`와 채널 조건에서 OFDM, AFDM, OTFS, DD-a-OFDM 모두
**10,485,760개의 정보·데이터 비트**를 측정한다. 모든 파형과 탐색 지점에
같은 비트 수를 적용하며, 오류 수에 따른 조기 종료는 하지 않는다. BER은
실제 측정한 데이터 비트 중 잘못 복구한 비트의 비율로 계산한다. 알려진
파일럿·프리픽스·보호구간·패딩은 데이터 비트 수와 오류 집계에서 제외한다.

모든 격자 칸이 비부호화 16-QAM 데이터라면 한 프레임은
`256 × 64 × 4 = 65,536`비트이므로, 이 측정량은 정확히 **160프레임**이다.
파일럿이나 예약칸을 도입하면 실제 데이터 비트 수에 맞춰 프레임 구성을 다시
계산하며, 네 방식의 공통 정보 비트 측정량은 유지한다. 이번 결정으로 구체적인
파일럿·보호구간 배치를 정한 것은 아니다.

약 1천만 비트는 실제 BER이 `10^-5`라면 평균 약 105개의 오류를 관측할 수 있는
초기 측정량이다. [BER 측정량과 오류 수에 관한 설명](https://www.mathworks.com/help/comm/ug/analyze-performance-with-bit-error-rate-analysis-app.html)의
약 100개 오류라는 기준을 정밀도 계획의 출발점으로 참고했다. 이는 실제 오류
수를 보장하거나 오류 100개에서 중단한다는 뜻이 아니다. BER이 `10^-6` 정도면
예상 오류가 약 10개에 불과하므로, 이보다 낮은 BER의 정밀한 비교에는 측정량을
다시 검토해야 한다.

결과에는 실제 측정 비트 수·오류 수·BER 추정값·신뢰구간을 함께 기록한다.
오류가 0개이면 측정 비트 수와 함께 **오류 미관측**으로 표시하고, 실제 BER이
정확히 0이라고 해석하지 않는다. 신뢰수준과 구체적인 신뢰구간 계산법은 아직
정하지 않았다. 실제 BER 측정과 실행시간 검증도 아직 수행하지 않았다.

## 대역폭 결정과 근거

네 방식의 공통 명목 격자 대역폭은 `B = N × Δf = 256 × 234.375 kHz = 60 MHz`다.
[Starlink Ku 신호 관측 연구](https://radionavlab.ae.utexas.edu/wp-content/uploads/starlink_structure.pdf)의
채널당 240 MHz와 같은 부반송파 간격을 유지하면서, BER 반복 계산의 부담을
줄이기 위해 격자 크기를 1024에서 256으로 줄였다. 이는 계산 편의를 위한
실험 설정이며 STARLINK-5285가 사용한 실제 대역폭이라는 뜻은 아니다.
명목 대역폭 기준 지연 분해능 `1/B`는 약 16.7 ns로, 240 MHz의 약 4.17 ns보다
낮다. 따라서 나중에 다중경로 채널을 정할 때 이 차이를 해석에 반영해야 한다.
첫 BER 비교의 왼쪽·오른쪽 가장자리 보호칸은 각각 0개로 정했다. 네 파형에
같은 규칙을 적용하고, 보호칸을 둔 경우는 이후 별도의 민감도 실험에서 살펴본다.
이는 계산 및 비교를 위한 단순화이며, 실제 송신 신호에 보호 대역이 없다는
주장은 아니다. 중앙 DC 칸도 비우지 않아 256개 주파수 칸을 모두 사용할 수
있다. DC를 비운 경우 역시 이후 별도로 비교한다. 데이터·파일럿 배치와
실제 스펙트럼 점유 대역폭은 아직 미정이며, 60 MHz 격자 폭을 실측 점유
대역폭과 동일시하지 않는다.

설정은 이번 비교에 채택하지 않았다.

## 평가 지표

1차 지표는 BER(잘못 수신한 정보 비트 수 / 전송한 정보 비트 수)로 확정했다.
비교 축은 수신 `Eb/N0`로 확정했다. 파형 자체의 차이를 먼저 보기 위해
첫 비교에서는 오류 정정 부호화를 적용하지 않는다. 부호화된 경우는 나중에
네 파형에 같은 부호를 적용하는 별도 실험으로 다룬다. `Eb/N0` 예비 탐색은
위와 같이 정했다. 반복 측정은 각 지점의 공통 총 데이터 비트 수로 종료하며,
세밀 측정 구간과 신뢰구간 계산 세부 사항·보조 지표는 이후 결정한다.

## 통과 구간 다시 계산하기

Python 3.12 이상 환경에서 이 폴더를 현재 작업 위치로 두고 실행한다.

```powershell
python -m pip install -r requirements.txt
python select_pass.py
```

`select_pass.py`가 출력한 결과를 `scenario.json`의 `selected_pass`와 비교한다.
보정 전 최대 공통 도플러도 함께 계산하려면 다음 명령을 사용한다. 이 옵션의
출력에는 `selected_pass`와 `common_doppler_envelope`가 함께 포함된다.

```powershell
python select_pass.py --doppler-envelope
python select_pass.py --doppler-envelope --doppler-step-s 0.125
```

좌표 변환에는 WGS-84와 1차 TEME→ECEF 회전을 사용하고, 원본과 같이 UTC를
UT1의 근사값으로 사용하며 극운동은 생략한다.
